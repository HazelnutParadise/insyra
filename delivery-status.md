## Latest Milestones
- 2026-09-12 `one-value-one-cell`: `NewDataList` flattens slices on purpose, so a list reads the way a pandas Series does, and there was no way to opt one argument out short of leaving the constructor for `Append` — which never flattens but cannot be mixed into the same call. `Cell(v)` is that opt-out, inline among ordinary values, and the mark is removed on the way in so the cell holds the value at its own type. Every entry point that takes a value from the caller unwraps it, the ones that never flatten included, so `Append(Cell(x))` and `Append(x)` agree and writing the first for consistency is not a trap; the search side unwraps too, so `Count(Cell(x))` matches. A bare slice still flattens, which the owner ruled on rather than leaving implicit.
- 2026-09-12 `identify-uncomparable-cells`: a cell value Go cannot compare used to crash the library and go missing at the same time. `Counter` keyed a `map[any]int` by the cell, so an unhashable value panicked there, and `equalCell` answered "not equal" for anything uncomparable, so `Count`, `FindAll`, `Replace` and `IsEqualTo` never found it. **Reachable without trying**: `convertSQLValue` keeps a binary column as `[]byte` on purpose, so reading a BLOB column and calling `Counter` took the process down while `Count` returned 0 for a value sitting in two rows, reproduced end to end against sqlite. One rule now covers it — a cell Go cannot compare is identified by its type and content — through a new `encodeCell`, the exported `UncomparableKey` and `ToMapKey`. Three things had to be true and none was optional: the encoding had to recurse (the old `%T:%v` fallback made `[]any{1}` and `[]any{"1"}` one group in `GroupBy`, `Pivot` and `Merge`, and a stand-in key built on it would have inherited that on day one); the comparability test had to be `reflect.ValueOf(v).Comparable()`, because `TypeOf(...).Comparable()` reports true for `[2]any{[]int{1},2}` and `struct{X any}{[]int{1}}` and both still panic on `==`; and `Count` had to move with `Counter`, or the same value would be counted twice by one and not found by the other. Scalar group keys are unchanged byte for byte. Fable was consulted on the naming and on whether the recursion belonged in this change; both of its rulings were taken, and its correction of the `TypeOf`/`ValueOf` mistake is the reason the fix works on the two shapes I had missed.
- 2026-09-12 `one-warning-per-unconverged-rotation`: `GPForth`/`GPFoblq` warned on every start that hit its iteration cap, and `insyra.LogWarning` pushes into the global error buffer, so with twenty starts a geomin or simplimax rotation could log twenty warnings and leave twenty buffer entries while the chosen solution had converged — the informed Varimax start warned too. Per-start runs now report at debug level; `FaRotations` warns once, naming the method, start count and cap, only when the solution it chose did not converge. Pinned by two tests that capture the logger and count buffer entries.
- 2026-09-12 `default-restarts-follow-psych`: the two questions `oblimin-honours-its-start` left, decided from the three R sources (GPArotation 2026.8-2 `R/GPFRS.R`, psych 2.6.5 `R/faRotate.r` and `man/fa.Rd`, fungible `R/faMain.R`). The rule stays lowest-criterion-among-converged: GPArotation's engine and fungible select the minimum, psych's hyperplane count chose the same basin on every fixture measured, over-factored included. The default becomes 20: psych's manual calls multiple restarts "strongly encouraged (see Nguyen and Waller)" and its author changed the default on a real local-minimum example; fungible defaults to 10; `ENG.md` names R as the reference and the baseline script calls `psych::fa` with its defaults. Measured on the twenty datasets in the suite, default loadings move by at most 1.2e-5 and 240 of 240 oblimin starts converged. **The cost was not the search**: twenty oblimin starts take 1.5 to 9 ms, while the informed Varimax start at `eps 1e-8 / maxit 5000` hit the cap on five datasets at 76 to 86 ms each. It now runs at the rotation's own tolerance, 0.03 ms.
- 2026-09-12 `oblimin-honours-its-start` (ST-12, no issue): `FaRotations`'s oblimin arm built its own identity start on every pass and ignored the one it was handed, so `Restarts: 20` ran the same computation twenty times — measured, 202 ms to return the 9.9 ms answer — while `Docs/stats.md` promised a search. Decided on the statistics and on the R references rather than on the comment's SPSS claim: `Restarts` is a multi-start minimisation and a start that is not used is not a start; `psych::faRotations` (2.6.5) passes `Tmat = initial` to `GPArotation::oblimin` with no per-method exception, and `GPArotation::oblimin()` has `randomStarts`. SPSS is single-start (IBM Algorithms, FACTOR: "C is initialized to Im"), which is `Restarts: 1`, left bit-identical — measured on eight configurations and structural, since `buildStarts` returns the identity alone. Measured on the review's synthetic table: with three factors every start reaches the same minimum (`f` moves by 4e-12); with four, a random start reaches a basin 47 times lower (0.0444 to 0.00094) whose `Phi` has an off-diagonal of 0.905, so the docs now say to look at `Phi` before preferring a multi-start result. A threshold before a random start may displace the identity was considered and rejected: neither reference has one. Reading both references also found that our selection rule follows GPArotation's engine (minimum `f`) while psych ranks by hyperplane count, and that psych 2.6.5 changed `n.rotations`'s default from 1 to 20; both are a follow-up.
- 2026-09-12 `parquet-foreign-column-types` ([#371](https://github.com/HazelnutParadise/insyra/issues/371), Q-11): `getVal`'s fallback returned `arr.String()`, the string form of the whole array, ignoring the row index, so a column type the reader did not handle read back as one identical string in every row with `Read` returning a nil error and `Err()` nil. Invisible on files this library wrote, because `Write` emits only seven Arrow types. Measured by writing nine foreign types and reading them back: eight were wrong, and **Dictionary was not among them** despite the issue listing it, because pqarrow materialises it as its underlying type — which mattered, since a pandas `category` column was the most common case on that list. Twenty Arrow types now have a faithful Go representation, including `Decimal128`/`Decimal256` through [go-decimal](https://github.com/TimLai666/go-decimal), whose `big.Int` coefficient and `int32` scale carry the full 38-digit range exactly (an `int64` coefficient could not). The rest read as `nil` with the column name and Arrow type on the table's `Err()`. Two things the implementation ran into: a DataList cell cannot be a slice, because `NewDataList` flattens every `reflect.Slice`, so `Binary` reads as a `string` holding the raw bytes rather than a `[]byte`; and ordering a decimal correctly needs `decimal.Cmp`, with no interface to dispatch on, so `internal/algorithms` imports go-decimal and it is a core dependency rather than a `parquet`-only one. Without that branch a column of 9.5, 10.2 and 100.0 sorted 10.2, 100.0, 9.5.
- 2026-09-12 `orthogonal-rotation-starts` ([#373](https://github.com/HazelnutParadise/insyra/issues/373), ST-11): `FactorAnalysis` with `Rotation.Restarts > 1` returned loadings that no longer described the fitted model. A rotation criterion is minimised over a constrained set, and the gradient projection algorithm only keeps an iterate on it if the start is on it; two of the starting points added for `Restarts > 1` were Promax and Target matrices, which are oblique. **The defect was wider than the issue**: it is not confined to the orthogonal family, because `FaRotations` premultiplies the loadings by the start instead of passing it to the algorithm, and the oblique parameterisation is `Λ = A·(T')⁻¹`. Measured on the review's own synthetic table, four of ten methods were wrong at `Restarts ≥ 2` (`max|L·L' − Lu·Lu'|` = 0.287, matching the issue), and BentlerQ broke its own oblique invariant by 0.763. Every start is now orthogonal and verified before use, and `Restarts` is the number of starts rather than a bound on the random ones only. A second defect in the same loop came with it: the candidate chosen among restarts never carried the convergence flag, so `RotationConverged` was a constant true — all nine iterative methods reported convergence after one iteration at a tolerance of 1e-12. Three tests were repaired along the way: the one that pinned the defect and asked to be replaced, `TestRestartsParameter` which ran GeominQ alone and so only ever checked the oblique invariant, and `TestRotationConvergedFlag` which tried to cripple a rotation with `opt.MaxIter` (extraction only, never reaches the rotation) and wrote its assertion as a `t.Logf`.

- `NewDataList`'s flattening of slices is deliberate and stays, including for `[]byte`. The escape hatch is per-argument (`Cell(v)`) rather than a change to the rule, so the pandas-like reading of the constructor is untouched (one-value-one-cell).
- `ToMapKey` was named twice before it settled. `KeyOf` promised "the key for this value" and delivers the key for this *Go* value, which differs on integer width; `CounterKey` bound a general helper to its first caller, when a caller's own map, set or index hits the same panic. All three renames landed before release (one-value-one-cell, identify-uncomparable-cells).
- A cell Go cannot compare is identified by its type and content, and that one rule covers counting, searching, matching and grouping. The alternative considered and rejected was a new comparable cell type for bytes (`type Bytes string`): it would have left `[]byte` and `Bytes` as two unequal ways to say the same thing, failed the type assertion people write by habit, and still not removed the `Counter` panic, because `[]int` cells reach it through `Append` regardless (identify-uncomparable-cells).
- `Counter` keeps `map[any]int`. A stand-in key was chosen over changing the signature to carry the original value: comparable values keep keying by themselves, so `counter[1]` is untouched, and nothing breaks for the ordinary case (identify-uncomparable-cells).
- Whether `Counter` should merge `int(1)` and `int64(1)` is still open and deliberately untouched (identify-uncomparable-cells).
- A Parquet column type the reader cannot represent reads as `nil` with the reason on the table rather than as plausible text, and the set of types it can represent was widened first so the refusal applies to a small residue. Reading each cell as its own string via `arr.ValueStr(i)` was measured to work for every type tried, and rejected: a decimal money column would become a text column with no signal, which is the silent-downgrade class this review exists to remove (parquet-foreign-column-types).
- A decimal is stored exactly, orders by value, and is **not** a number to `IsNumeric`, following the `time.Time` precedent rather than widening what numeric means library-wide. Whether that is right for money is recorded as a follow-up (parquet-foreign-column-types).
- `github.com/TimLai666/go-decimal` is a core dependency, not a `parquet` one, because ordering needs `decimal.Cmp` in `internal/algorithms` and package functions cannot be reached through an interface (parquet-foreign-column-types).
- A rotation start must lie on the criterion's own manifold, and the minimal form of that is the one `GPArotation` already uses: every start orthogonal, for the oblique family as well as the orthogonal one. Threading the start into `GPForth`/`GPFoblq` as its `Tmat` instead of premultiplying the loadings was considered and rejected as a refactor without a correctness argument — with an orthogonal start the two are the same optimisation (`T = S·R` gives `L·(T')⁻¹ = L·S·(R')⁻¹` and `T'T = R'R`), so it would only admit start matrices `GPArotation` does not use (orthogonal-rotation-starts).
- Among restarts, a converged solution beats one that did not converge whatever their criterion values; comparing criterion values only means something among runs that finished. When none converged the best is still returned, reported as not converged, rather than failing (orthogonal-rotation-starts).
- `oblimin` uses its starts like every other method. Decided on what `Restarts` means and on both R references, not on the comment's SPSS claim: SPSS is single-start and that is `Restarts: 1`, which stays bit-identical. No threshold before a random start may displace the identity, because neither `GPArotation`'s engine nor `psych::faRotations` has one (oblimin-honours-its-start).
- Among starts, the lowest criterion value among those that converged wins, not psych's hyperplane count: the criterion defines the rotation, `GPArotation`'s engine and `fungible::faMain` both select its minimum, and measured on three fixtures with twenty starts the two rules chose the same basin every time, including the over-factored one (default-restarts-follow-psych).
- `Restarts` defaults to 20, psych 2.6.5's `n.rotations`, because psych is the reference implementation and a single start is the estimator only when the criterion is unimodal; SPSS and `GPArotation` stay reachable as `Restarts: 1`. The informed Varimax start runs at the rotation's own tolerance, which is where the 85 ms default cost was (default-restarts-follow-psych).
- `AtomicDoAll` narrows to a closed `Lockable` interface rather than keeping `...any` with a louder runtime error: a value that cannot be locked is a mistake the compiler can catch (core-lock-and-snapshot).
- A custom CCL function that reads another table is made safe by locking every table involved from outside the CCL call. Locking from inside the function was measured to deadlock against the mirror image, so it is documented as the thing not to do (core-lock-and-snapshot).
- `ExecuteCCL` gets no `ExecuteCCLErr`: typed errors already reach callers through `errors.As` (core-lock-and-snapshot).
- A number written as text follows `encoding/json`'s rule. Sort keys, cache keys and `Show`'s display are deliberately excluded, and a `nil` category keeps the documented name `<nil>` (format-numbers-as-text).
- `ROLLING_*` stays O(rows × window): a running accumulator would change results by drift where recomputing does not (ccl-performance).
- `Classes()` returns an empty list with a reason rather than changing its signature, because `Classifier` is a public interface; consumers keep a nil guard since third parties can still return nil (ml-classes-never-nil).
- CCL boolean coercion stays and the documentation was corrected, rather than the reverse: `IF`, `AND`, `OR`, `CASE`, `&&` and `||` all read their condition the same way, so a strict `&&` would have split the language (batch 8).
- CCL comparison resolves in one order — numbers, then text, then an error — so `'10' > '9'` keeps its documented numeric reading while `'abc' < 'abd'` gains a real one (batch 8).
- `ColumnRange`/`RowRange` stay internal and an expression that ends with one is an error, instead of exporting them so callers can type-assert an implementation detail (batch 8).
- A CLI check reads `ColNames()`/`RowNames()` rather than the `Get*` lookups, because a check must not record an error on the user's table; `checkTableErr` uses `PopErr` so a sticky error cannot fail the next REPL command (batch 7).
- `CSVWriteOptions.SanitizeFormulas` defaults off: it changes the value written, and `ToCSV`'s output stays as it was (batch 6, flagged on #285 for the owner to overrule).
- `AtomicDoAll` inside an `AtomicDo` on one of its instances now runs inline without locking the others (trust-zone rule), instead of deadlocking.
- CCL keywords are case-insensitive; out-of-range Excel references are errors; aggregates skip `NaN`; `MapContext` orders columns by name.
- `plot.SavePNG` online fallback is opt-in (batch 3).
