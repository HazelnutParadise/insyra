# Proposal: default-restarts-follow-psych

## Why

`oblimin-honours-its-start` left two questions open, both about which reference `FaRotations` follows: the rule that picks among starts, and how many starts the default runs. Both are decided here on the statistics and on what the R packages do.

**The rule.** A rotation is defined as the minimiser of its criterion, and a multi-start search exists to find the global minimum of that criterion, so the solution to keep is the one with the lowest criterion value. That is what `GPArotation`'s engine does (`.GPA_RS_engine`, 2026.8-2: strict minimum `f`) and what `fungible::faMain` does (`which.min` on the criterion; its solutions list is "ordered so 1 is minimum discrep value"). `psych::faRotations`, which credits fungible for the technique, instead ranks starts by hyperplane count — the share of loadings below `hyper = .15` in absolute value — then complexity, then fit. Measured on the three fixtures in `rotation_starts_test.go` with twenty starts each: on the two well-specified ones every start reaches the same basin and the two rules differ only in which numerically-equal start they name; on the over-factored one both rules pick the same lower basin (hyperplane 0.75 against 0.667, `f` 0.00094 against 0.0444). psych's rule offers no protection the criterion does not, and it depends on a cutoff our API does not expose. The rule stays as `orthogonal-rotation-starts` set it: the lowest criterion value among the starts that converged.

**The default.** psych 2.6.5 (2026-05-15) changed `fa()`'s `n.rotations` from 1 to 20; its manual says multiple restarts "are strongly encouraged (see Nguyen and Waller)" and that a real example convinced the author to stop ignoring that advice. `fungible::faMain` defaults to 10 random starts. `GPArotation` and SPSS default to a single identity start. psych is this package's reference implementation — `ENG.md` names R as the reference for `stats`, `stats/testdata/crosslang_baseline.R` calls `psych::fa` without `n.rotations`, so a baseline generated by a current psych already uses twenty — and the statistics point the same way: a single start finds a local minimum, and the estimator is the global one. The default becomes 20.

Measured on the default path (Kaiser count, MINRES, oblimin) over the twenty datasets in `factor_analysis_test.go`: twenty starts move the loadings by at most 1.2e-5 and never to a different solution, and every one of the 20 × 12 oblimin starts converged. The cost, however, was 85 ms on five datasets against 0.2 to 0.7 ms at one start — and the rotation was not where it went. The informed Varimax start that `buildStarts` adds runs at `eps = 1e-8, maxit = 5000`, hits the cap on those five datasets, and costs 76 to 86 ms each time; at the rotation's own `1e-5 / 1000` it costs 0.03 ms, and the twenty oblimin starts together cost 1.5 to 9 ms. A start does not need eight digits of precision; it needs to be orthogonal, which is verified separately.

## What Changes

- **BREAKING**: `DefaultFactorAnalysisOptions()` sets `Rotation.Restarts` to 20, and `Restarts` left at zero means 20. `Restarts: 1` still means the single identity start, which is what SPSS and `GPArotation` do by default.
- The informed Varimax start runs at the rotation's own tolerance and iteration cap instead of `1e-8 / 5000`.
- The selection rule is unchanged and now documented as a decision: lowest criterion value among the starts that converged, as `GPArotation`'s engine and `fungible::faMain` do.
- `Docs/stats.md`, the struct comment, and the skill reference say the default is 20 and why, and say what rule picks among starts.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `stats-factor-rotation`: adds the requirement that the default number of starts follows psych and that the informed start is built at the search's own tolerance.

## Impact

- Every `FactorAnalysis` call that does not set `Rotation.Restarts` now runs twenty starts. On the twenty datasets in the suite the loadings move by at most 1.2e-5, inside the 2e-5 R parity tolerance, and the same basin wins each time. A caller who wants the single-start result sets `Restarts: 1`.
- Default-path cost on those datasets goes from 0.2 to 0.7 ms to 1.5 to 9 ms, rather than to 85 ms.
- `buildStarts` gains `eps` and `maxIter` parameters; its four test call sites change with it. Results at `Restarts > 1` for every method can move at the 1e-10 level, because the informed start is computed to a different tolerance.
- The per-start "did not converge" warning `GPFoblq`/`GPForth` log is unchanged. With twenty starts a criterion that has local minima (geomin, simplimax) can log it several times per call even when the chosen solution converged; that is pre-existing behaviour for anyone who set `Restarts: 20` and is recorded as a follow-up rather than changed here.
- Both changelogs gain a `stats` entry; `delivery-status.md` records both decisions; the `AGENTS.md` follow-up that asked them is deleted.
