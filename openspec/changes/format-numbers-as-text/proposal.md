# Proposal: format-numbers-as-text

## Why

Insyra writes a `float64` as text in several places, and most of them use Go's default `%v`, which switches to scientific notation as soon as a value reaches one million. A New Taiwan dollar revenue column computed as `A * B` from a unit price of 1,500 and a quantity of 1,000 comes out of CCL as `營收：1.5e+06`, and `ToCSV` writes `1.5e+06` into the file. One million is an ordinary amount in this library's main currency.

The library does not agree with itself about this. `ToJSON` goes through `encoding/json`, which writes `1500000` and switches to an exponent only below 1e-6 or at 1e21 and above — the same rule JavaScript uses. Python writes `1500000.0`. Only the paths built on `%v` write `1.5e+06`.

## What Changes

- **One shared rule for writing a number as text**: the one `encoding/json` already applies in this library. A value with a magnitude from 1e-6 up to (not including) 1e21 is written as a plain decimal; anything outside keeps the exponent form it has today. `NaN`, `+Inf` and `-Inf` are unchanged.
- **Applied where a value becomes text a person reads or a file stores**: CCL's string functions (`&`, `CONCAT`, `LEN`, `TOSTR` without a format, `UPPER` and the rest), `ToCSV` cells, `DataList.ToStringSlice`, and the column names `OneHotEncode` and `Pivot` generate from values.
- **Not applied where the text is not output**: the string comparison `internal/algorithms` falls back to when sorting mixed types (changing it would reorder data), accel's cache keys, and `Show`'s fixed-width display format.
- **`nil` is untouched.** `OneHotEncode` documents that a `nil` category is named `<nil>`, and its collision check is built around that name; `Pivot` names it `<nil>` through an explicit branch with the same kind of collision guard. Neither is a `%v` leak, and this change is about numbers.

## Capabilities

### New Capabilities

- `number-text-format`: a number written as text by insyra follows one rule, the one its JSON output already follows.

### Modified Capabilities

(none)

## Impact

- `internal/utils` (new `FloatText`, `ValueText`); `internal/ccl/stdlib_string.go`; `datatable_csv.go`; `datalist.go`; `datatable_encode.go`; `datatable_pivot.go`.
- `Docs/CCL.md`, `Docs/DataTable.md`, `Docs/DataList.md`, `skills/insyra/`, both changelogs, `AGENTS.md` (the follow-up is resolved and removed), `api-review.md`.
- **BREAKING.** CSV files, CCL strings and `ToStringSlice` change for floats from 1e6 to 1e21 and from 1e-6 to 1e-4 (`1.5e+06` becomes `1500000`, `1e-05` becomes `0.00001`). Read back, every number is the same value. Column names generated by `OneHotEncode` and `Pivot` change the same way, so code that looks a column up by its old name (`price_1.5e+06`) stops finding it. An `int` and a `float64` category with the same large value now produce the same one-hot name and are rejected at fit time, exactly as `int(1)` and `float64(1)` already are; `Pivot`'s label-collision guard rejects the same case.
- Values that stay in exponent form (below 1e-6, at or above 1e21) are written byte-for-byte as before.
