# Changelog

Changes that affect people using Insyra, grouped by package the same way release notes are. `## Unreleased` holds what will go into the next release.

v0.3.0 and everything before it is not repeated here — see [GitHub Releases](https://github.com/HazelnutParadise/insyra/releases).

## Unreleased

### Core

- Fixed ordering losing precision on integers. Every integer was compared through `float64`, so any two `int64` above 2^53 looked equal and `Sort`, `SortBy`, `Pivot` and `Describe`'s min/max ordered them wrongly. Integers now compare exactly, including mixed signed/unsigned and values past `int64`.
- Fixed `HermiteInterpolation` using the wrong basis: it satisfied none of the derivative conditions it is named for. It now passes through every value and matches every supplied derivative, and reproduces low-degree polynomials exactly.
- `TryParseTime` accepts the common layouts that carry no zone — `2006-01-02 15:04:05`, `2006-01-02T15:04:05` and `2006-01-02 15:04`, plus `2006/01/02 15:04:05` and `2006/01/02 15:04` (a `/`-separated date takes no `T`) — read as UTC. CCL's date functions and `datafetch` were silently treating those strings as text.
- Fixed `ShowTypes` printing columns as `A, AA, AB, B, …` past column 26, with or without column names; it now uses the same order as `Show`. `ShowRange`'s documentation now states the rule the code implements: the end index is exclusive and a negative end counts back from the end and stays exclusive, like a Python slice, so pass `nil` to run to the end.
- `Close()` on a `DataList` or `DataTable` no longer discards an operation that was already waiting for the lock. Close stops the locking, not the queued work.
- Fixed `DataList.ReplaceLast` replacing the last `NaN` cell instead of the last cell equal to `oldValue` when the list ended in `NaN` (`[5, NaN].ReplaceLast(5, 0)` gave `[5, 0]`).
- Fixed `ReadJSON_File` loading integer literals as `float64` while `ReadJSON` loaded them as `int64`; both now decode through the same path, so large integers keep full precision from a file and a file holding a single object loads as one row.
- Fixed several `DataTable` behaviours found by the API review: `GetElementByNumberIndex`, `SetRowToColNames`, and `SetColToRowNames` no longer panic on an out-of-range index (they set `Err()`), and `GetElementByNumberIndex` accepts a negative column index; a `Filter*` call with no match returns an empty table whose methods are safe to call; `FilterRows`/`FilterCols` no longer panic on a ragged table; `DropRowsByIndex` resolves negative indices against the original row count and ignores duplicates (`(-1, 0)` used to keep row 0, `(1, 1)` used to delete two rows); `Transpose` keeps every row name (names beyond the old column count were lost); `AppendRowsByColIndex` grows the table to the addressed column instead of dropping the value; `DropColsContainNumber`/`DropRowsContainNumber` recognise every built-in integer and float type (an `int64` column from CSV inference was not dropped), while a named numeric type such as `time.Duration` is still kept; and `Mean` divides by the number of numeric cells.
- `Config.SetLogLevel`, `SetUseColoredOutput`, `SetDontPanic`, and `SetDefaultErrHandlingFunc` are now atomic, so calling them while another goroutine logs is no longer a data race. The error hook installed by `SetDefaultErrHandlingFunc` runs on one goroutine behind a queue of 1,024 calls, in order, instead of one goroutine per warning; a call that finds the queue full still reaches the hook, on its own goroutine and possibly out of order. Importing the package no longer prints the "Welcome to Insyra" banner; the CLI REPL prints it at startup.
- `DetectEncoding` no longer misjudges a UTF-8 file whose multi-byte character straddles its 8 KB sample boundary.
- `DataList.IsEqualTo` and `IsTheSameAs` no longer panic on cells Go cannot compare with `==` (such as a struct holding a slice); such a cell is compared by its type and content. `ClearNaNs`, `ClearNils`, `ClearNilsAndNaNs`, `ClearNumbers`, `DropAll`, and `ClearStrings` filter in one pass, with the same results, instead of quadratic in-place deletion or a goroutine per call; `Update` records itself, not `ReplaceAtIndex`, in `Err()`. `DataTable.FindColsIfContains`/`FindColsIfContainsAll` no longer leave a warning on every column that lacks the value; `Count` and `Clone` drop their goroutine fan-out. `AppendRowsByColName` (and therefore `ReadJSON`/`ReadJSON_File`) adds new columns in sorted key order, so a JSON document no longer loads with a different column order on each run.
- CCL: `NULL`, `TRUE` and `FALSE` are keywords in any case instead of column references; `@` used as a value gives each row its own slice (every cell used to show the last row); a sequence function inside another sequence or aggregate function (`LAG(LAG(A,1),1)`, `SUM(LAG(A,1))`) keeps the whole column; a `LAG`/`LEAD`/`ROLLING_*` shift or `REPEAT` count that is `NaN`, infinite or beyond `int64`, and a `REPEAT` result whose length overflows `int`, are errors instead of panics, while a shift or window longer than the column still gives `nil` cells; the function registry is safe to extend while another goroutine evaluates; `engine/ccl.NewMapContext` orders columns by name so `A`/`B` are deterministic.
- `ToCSV` returns the error from its final flush and, when the write succeeded, the error from closing the file; a small table written to a broken pipe used to report success.
- Added `PopErr()` to `DataList` and `DataTable`, which returns the current `Err()` and clears it, and `SetErr(packageName, funcName, msg, args...)`, which records an error on the instance the way insyra's own methods do (a warning is logged and `Err()` is replaced). `IDataList` and `IDataTable` include both.
- The global error buffer is bounded at `ErrorBufferCapacity` (1536) records and drops the oldest instead of growing without limit. It is documented as a diagnostic log rather than an error-handling API, and nine of its accessors (`PopError`, `PopErrorByPackageName`, `PopErrorByFuncName`, `PopErrorAndCallback`, `PeekError`, `GetErrorsByLevel`, `GetErrorsByPackage`, `PopErrorInfo`, `HasErrorAboveLevel`) are deprecated in favour of `GetAllErrors`, `PopAllErrors`, `HasError`, `GetErrorCount` and `ClearErrors`.
- Reading a CSV (`ReadCSV_File` and `csvxl`'s CSV readers) decodes UTF-16/32, the ISO-8859 parts, Windows-1250 through 1258, KOI8-R/U, Shift-JIS, ISO-2022-JP, EUC-JP, EUC-KR, IBM866 and Macintosh, plus the usual aliases, with separators and case ignored (`ISO-8859-1`, `iso8859_1` and `latin1` are the same). Before, only UTF-8, UTF-16, Big5 and GB18030 had a decoder: `iso-8859-1`, which the detector names correctly, was copied into the table as cells that are not valid UTF-8, and `utf-16be` without a byte-order mark was read as little-endian. Any other name still reads as it did, including ISO-2022-KR, ISO-2022-CN, IBM424 and IBM420, which the auto-detector can report and which are read as raw bytes, except by `csvxl.ReadCsvToString` (see `csvxl`).
- `DetectEncoding` recognises a UTF-32 byte-order mark; it was reported as UTF-16, whose BOM is a prefix of it.
- Added `DataTable.ToCSVWithOptions` and `CSVWriteOptions`, with `SanitizeFormulas` to prefix a cell starting with `=`, `+`, `-` or `@` with a single quote so a spreadsheet does not execute it. It is off by default — it changes the value written, and `ToCSV`'s output is unchanged.
- Fixed `ToSQL` on SQLite failing to append to a table whose name contains a space: the column lookup interpolated the identifier instead of quoting it like every other statement.
- CCL failures say which phase failed and where. A compile failure names the expression, the byte offset of the problem and the text at it (`cannot compile "(A B)" at offset 3 (near "B"): expected ')'`); an evaluation failure names the row (`cannot evaluate "A / B" at row 1: division by zero`), or says nothing about rows when the expression does not depend on one. `AddColUsingCCL`, `EditColByIndexUsingCCL` and `EditColByNameUsingCCL` used to report both under the prefix `Failed to apply CCL on DataTable after 213.792µs`, which answered neither question and put a stopwatch reading where the cause belonged. `position N` used to mean a byte offset in one place and an index into the token list in another; it is always a byte offset now, snapped to a character boundary so a non-ASCII expression points somewhere real. Two messages printed Go internals (`unexpected token: {5 )}`, `invalid range operands: &{: 0x1d48…}`) and now print the source text. A failure inside `ExecuteCCL` names the statement it came from, so a script of five lines no longer reports `Failed to execute CCL statement: division by zero` with nothing to say which line produced it. The failures are exported types — `ccl.CompileError` and `ccl.EvalError` from `engine/ccl` — and `ErrorInfo` gained a `Cause` field and an `Unwrap`, so `errors.As(dt.Err(), &compileErr)` works instead of matching on message text. `Unwrap` returns nil for the nil `*ErrorInfo` that `Err()` gives after a call that succeeded, so that check does not panic on a formula that worked. They are still recorded as warnings, like every other `DataTable` error.
- CCL no longer repeats work whose answer cannot change. In `AddColUsingCCL`, `EditColByIndexUsingCCL` and `EditColByNameUsingCCL`, an aggregate that does not mention `#` is computed once before the rows are walked, though not ahead of a table with no rows, instead of once per row over a fresh copy of the column: on 20,000 rows `A / SUM(A)` goes from 2.1 s to 1.0 ms, and the z-score `(A - AVG(A)) / STDEV(A)` from 6.2 s to 1.8 ms. An aggregate that does mention `#` is row-dependent and still runs per row. Three smaller costs on the same path: a string is only offered to the date parsers when its first character could start a date, `REGEX_MATCH` compiles each pattern once instead of once per row, and `ROLLING_*` converts its column once rather than once per window per element. **No result changes**, and `ROLLING_*` stays proportional to the window on purpose, because a running accumulator would drift where recomputing the window does not.
- `AtomicDoAll` skips a nil instance, whether a nil `*DataList`, a nil `*DataTable` or a nil value, instead of panicking; the instances next to it are still locked.
- Fixed `GroupBy` computing from the parent's data as it was when `Aggregate` ran rather than when the groups were formed. It kept pointers to the parent's columns, so a change to the parent between the two calls reached the result (a group holding `3` summed to `102`), and `Aggregate` read that data without a lock while another goroutine could be writing it. `GroupBy` now copies the column data it groups.
- Fixed searching, counting, replacing and dropping by value missing an integer stored as another Go integer type. A CSV load stores integers as `int64` while Go code writes `2` as `int`, and the comparison used `==`, which never matches an `int64` against an `int`: on a table read from CSV, `Count(2)` returned 0, `FindAll(2)` and `FindRowsIfContains(2)` found nothing, and `Replace(2, 0)` changed nothing. Integers now match by value, from `int8` to `int64` and `uint8` to `uint64`, in `Count`, `FindFirst`, `FindLast`, `FindAll`, the `Replace` methods, `DropAll`, `FindRowsIfContains(All)`, `FindColsIfContains(All)`, `DropRowsContain` and `DropColsContain`. A float still never matches an integer, so search with `2.0` to find `2.0`, and floats, strings, bools, `nil` and `NaN` match exactly as before. `IsEqualTo` and `IsTheSameAs` still compare type by type. These lookups also no longer panic on a cell Go cannot compare with `==`, such as a struct holding a slice; it is matched by its type and content. Searching for a float or a string is faster, because the comparison for the searched value's type is now picked once per call: a `Count` over a million cells went from 2.3 ms to 1.7 ms for floats and from 2.8 ms to 2.0 ms for strings.
- Fixed CCL giving a different answer on amd64 and arm64 when a count, digit count or date shift was too large for Go's conversion to an integer or a duration, which is undefined there. On Linux and Windows `MID('abc', 2, 10^300)` returned `""` while a Mac returned `"bc"`, `ROUND(x, NaN)` returned `NaN` on one and rounded to an integer on the other, and `DATEADD(d, 10^300, 'day')` produced a different wrong date on each. A character count or position past the end of a string now means "to the end" everywhere. A `NaN` count or digit count, a `DATEADD` day, month or year count that is infinite or beyond `int64`, or of more than about 292 years in hours, minutes or seconds, a date plus or minus more than 106,751 days, a `DAY`, `HOUR`, `MINUTE` or `SECOND` of more than about 292 years of seconds, and a row range bound that is `NaN` or outside the int32 range are errors instead of a wrapped-around value. Results for ordinary values are unchanged, including the conversions that drop a fraction, such as a fractional `DATEADD` day count.
- Fixed `Show` (and every other display path) printing a different number on amd64 and arm64. The formatter decided whether a float was a whole number with `v == float64(int(v))`, and that conversion is undefined in Go for a value outside `int`'s range: `2^63` printed as `9223372036854775807` on a Mac — an exact-looking integer one less than the value — and as `9.2234e+18` on Linux and Windows. Anything outside `int64`'s range now takes the exponent form everywhere. Whole numbers inside the range are unchanged.
- Fixed a Unix timestamp in milliseconds reading as the wrong date past 2262-04-11. The conversion multiplied the value into nanoseconds first, which overflows `int64` well inside the range it accepts, so `99999999999999` came back as 2216 instead of 5138.
- Fixed six values that came back wrong with nothing to show for it. A 16-digit (microsecond) timestamp read as seconds, so `2023-11-14` became `53872825-06-17`; the millisecond window also stopped short of the microsecond one, leaving a range that fell through to seconds. `CalcColIndex` produced column names its own `ParseColIndex` refused at the very top of the `int` range. `Show` printed `9999.99999` as `10000` — rounded to four places and trimmed of its trailing zeros, which reads as an exact integer. `IsNumeric` and the numeric read path disagreed about every named type over a numeric kind (`type Celsius float64`, `time.Duration`): `IsNumeric` called such a cell a number while `ToFloat64Safe` refused it and `ToFloat64` gave `0`, so `Mean` and `Sum` skipped it and `ToF64Slice` turned it into `0`. Both now read its value (a `time.Duration` reads as nanoseconds). `DataList.NearestNeighborInterpolation` answered the first value for a `NaN` x — every comparison against NaN is false, so the search never moved — and `LagrangeInterpolation` and `NewtonInterpolation` returned `NaN` with nothing in `Err()`; all three now return `NaN` and record the failure in `Err()`, like `LinearInterpolation` and `QuadraticInterpolation` already did.
- Fixed two tables with no column names failing to merge vertically. `NewDataTable(NewDataList(...))` leaves every column unnamed, and the duplicate-name check counted the empty name as a duplicate of itself, so the plainest constructor produced a shape that could not be merged with another of its kind. Unnamed columns now line up by their position among the unnamed ones; named columns still line up by name.
- CCL: a number literal too large for a `float64` is an error instead of silently becoming `+Inf` — `strconv.ParseFloat`'s error was being dropped. Exponent notation is now a literal form: `1e5`, `1.5e-3` and `2E+3` compile, where they used to split into a number and an identifier and fail with `unexpected token`, even though `VALUE('1e3')` always worked and CCL's own string output uses exponent form. An `e` only joins the number when a digit follows, so a column called `E` or `E1` is unaffected. `TOSTR(1.5, '%d')` and `TOSTR(1, '%')` report the mismatch instead of writing Go's own complaint — `%!d(float64=1.5)`, `%!(NOVERB)` — into the cell. Text that only looks like such a complaint because it was already in the value or the format, such as `TOSTR(A, '%s')` on `Item (MISSING)`, is written as it is.
- `Show` and every other display path print a struct value that implements `fmt.Stringer` as its text. The formatter ended in a branch that printed `<pkg.Type>` for a struct without asking whether it could print itself, so a Parquet decimal column showed as `<decimal.Decimal>` in every row. A struct without `String()` still shows its type name, a nil pointer still shows `<nil>`, and the stored value is unchanged.
- A string cell that is not valid UTF-8 is displayed as hex, the way a `[]byte` already was, instead of as quoted mojibake. Beyond being unreadable, the quoted bytes put the row one column out of alignment: `runewidth` scores a NUL at 0 and an invalid byte as one `U+FFFD`, while a terminal draws them however it likes, so no width calculation could be right. Such a string now renders as `00ff41`, truncated past 20 bytes with a count, which is ASCII, so the column lines up. Valid UTF-8 is untouched, CJK and emoji included, and the stored value does not change.
- `Counter` no longer panics on a cell value Go cannot use as a map key, and the lookups agree with it. `Counter` built a `map[any]int` keyed by the cell, so a value that cannot be hashed took the process down, while `Count`, `FindAll`, `Replace`, `DropAll`, `IsEqualTo`, `IsTheSameAs` and the `DataTable` find and drop methods treated it as unequal to everything, so `Count` reported 0 for a value sitting in two rows. This is reachable without trying: `ReadSQL` keeps a binary column as `[]byte` on purpose (BLOB, BYTEA, BINARY, VARBINARY, LONGBLOB). Such a value is now identified by its type and content: `[]byte{0, 255}` matches another `[]byte{0, 255}` but not a `[]int{0, 255}`, and integers nested inside it compare by value, as `Count` does. `Counter` keys it by the new `insyra.UncomparableKey`, which the new `insyra.ToMapKey(v)` builds for a caller indexing the whole map or keeping a map of their own over cell values; comparable values are still keyed by themselves, so `counter[1]` is unchanged, and a printed stand-in shows its type and a shortened form of its content, such as `[]uint8(00ff41)`. To read one value's count prefer `Count`, which matches integers by value where the map keys them by Go type. A scalar `NaN` cell is still unequal to another `NaN` in `IsEqualTo`; inside a slice, map or struct a `NaN` is part of the content, so two `[]any{NaN}` cells are equal and match each other. `GroupBy`, `Pivot`, `Merge` and `Describe` keep their existing keys.
- `insyra.Cell(v)` keeps one value in one cell when a constructor would otherwise flatten it. `NewDataList` flattens slices on purpose, so that building a list reads the way building a pandas Series does, and there was no way to opt one argument out short of leaving the constructor for `Append`, which cannot be mixed into the same call. `NewDataList(insyra.Cell([]int{1, 2}), 3, "a")` is three cells, and the first holds the slice at its own type. Every entry point that takes a value from the caller accepts the mark and removes it — `Append`, `Update`, `InsertAt`, the `Replace` and `Replace…With` methods of `DataList` and `DataTable`, `Shift`'s fill value, `UpdateElement` and the row appenders — including the ones that never flatten, so `Append(Cell(x))` and `Append(x)` mean the same thing; `Count(Cell(x))` and `Count(x)` agree too. A bare slice still flattens.
- An `insyra.UncomparableKey` prints the way the value writes itself. It rendered the encoded content, which for a struct is its fields, so an uncomparable value implementing `fmt.Stringer` showed its internals in a printed `Counter` result: a `decimal.Decimal`, what a Parquet `Decimal128` column reads as, printed its `big.Int`'s sign and words. Such a value now shows its own text, such as `decimal.Decimal(-340.0221114815)`, truncated by the same limit; a value without `String()` is unchanged. Identity still comes from the encoding, not the text, because a `String` may be lossy and two distinct values whose text matched must not merge into one count.
- Fixed `SortBy` mishandling a column that is not there. A missing index, name or number was reported by the internal `GetCol`, `GetColByName` or `GetColByNumber` lookup instead of `SortBy`, and a multi-level sort with one bad level still applied the others. Every level is now checked before any row moves, and a missing column records the error on `SortBy` and leaves the table unchanged. A config giving more than one of `ColumnIndex`, `ColumnName` and `ColumnNumber` still sorts by the documented precedence (index, then name, then number) and now logs a warning naming the fields it ignored; `Err()` stays nil. A config that gives none still sorts by the first column, and `Docs/DataTable.md` now says so: `ColumnNumber` counts only when it is not zero, so its zero value never overrides a name or an index.
- `engine/biindex`: `BiIndex.Set` moving a name onto another id now frees the name's old id, so a later `Assign` hands it out again. The old id used to be deleted without being freed, leaving a hole no `Assign` could reuse.
- CCL: a date plus or minus a number of days keeps the part of a day below an hour, which is what `Docs/CCL.md` has always said: the number counts days. The days were cut to whole hours, so `A + 0.0625` moved the date 1 hour instead of 1 hour 30 minutes and `A + 0.001` did not move it at all; they now move it 1 hour 30 minutes and 86.4 seconds. Whole and half days move exactly as before.
- CCL: comparing a string that is not a number with a number using `>`, `<`, `>=` or `<=` is an error, which is what `Docs/CCL.md` has always said (`"hello" > 5 // Error`). It returned `false`, so `A > 5` on a row where `A` held a word read as an ordinary answer. `==` and `!=` still report such a pair as unequal, a numeric string such as `'5'` still compares as a number, `nil` still compares as `false`, and two strings that are not both numbers still compare as `false`.

### CLI

- Environment names that would resolve outside the environments directory are now refused: an empty or absolute name, or one that escapes through `..` (`../x`, `a/../../x`). A name was previously joined straight onto the environments directory, so `../x` created or deleted directories outside it. Every other name, including ones with spaces or non-ASCII letters, still works.
- The command registry is guarded by a lock, so registering commands from several goroutines (embedders) is no longer a data race.
- Fixed a crash when `col`, `row`, `movavg`, `expsmooth` or `diff` failed to find or compute a result: the nil result was stored and the next save of the session panicked. They now return an error and store nothing.
- Variables holding `NaN` or ±Inf (a CSV with a blank cell) are saved and restored intact; previously such a table came back as an empty string, and such a list or raw value made the whole save fail. Every other variable is written exactly as before, and existing state files still load.
- `--env`, `--no-color` and `--log-level` placed before `newdl`, `addcol`, `addrow` or `show` now apply instead of being stored as data in the default environment.
- `run` no longer opens the interactive REPL when the script contains `env open`, and stops a script that runs itself after 16 nested levels.
- `db connect` lines are written to `history.txt`, the REPL history and `env export` with the password masked (URL, `user:pass@`, and `password=` forms, a quoted or space-containing `password=` value masked whole, including one written with spaces around `=`, a backslash-escaped quote inside single quotes or a `}}` inside braces); history files are created with mode 0600.
- `accel`'s usage no longer claims a `run` subcommand that does not exist.
- `help` now shows what `pca`, `regression` and `count` actually take. The first two accept `as <var>`, and `count` requires its value instead of marking it optional. The usage error for `save … sql` lists `rownames [true|false]`, matching its Usage.
- `count`, `find` and `replace` match the integers in CSV-loaded tables, and in every variable restored between one-shot commands. They compared the typed `2`, an `int`, with stored `int64` values and never matched: `count x 2` printed 0, `find x 2` printed `[]`, and `replace x 2 0` printed `replaced` and changed nothing.
- Database connections no longer print gorm's query log. Its default logger interpolates bound parameters into the message on a failing or slow query, so a `WHERE token = ?` put the token in the terminal and in anything capturing it. The CLI reports its own errors, so nothing is lost.
- Error messages name the command and the argument instead of handing back the standard library's text. `ttest single x abc` said `strconv.ParseFloat: parsing "abc": invalid syntax`; it now says `ttest: invalid mu "abc", expected a number`. Twenty-one places across `ttest`, `ztest`, `anova`, `chisq`, `movavg`, `expsmooth`, `shift`, `diffn`, `pctchange`, `rolling`, `expanding`, `ewm`, `quartile`, `percentile` and `fetch` read the same way now. The `strconv` error behind the message is still attached, so `errors.Is(err, strconv.ErrSyntax)` holds as it did.
- `kmeans` and `knn` match option keys without regard to case — `NSTART 3` works — and an unknown option lists the ones that exist. `knn` checks `weighting` and `algorithm` against their allowed values, case-insensitively, instead of passing the string straight through, so a misspelling is caught here rather than reaching the library as an unknown mode.
- `clone`, `replace`, `clean`, `fillna` and `count` tell a missing variable apart from one holding the wrong type. All five used to say "variable not found" for a variable that was right there, sending you after a typo that was not there.
- `help` lines its table up with the longest command name, so `knn_neighbors` no longer pushes its description out of line, and `read` and `env` have Forms and Examples — `env` has nine subcommands and listed none of them. `help` and tab completion read the command registry under its lock, through the new exported `commands.LookupCommand` and `commands.SnapshotRegistry`.
- `read sales.csv as x` says what to do instead of `unknown option "as"`. `read` only previews a file and supplies its own alias internally, so a user-supplied one arrived as a second `as` and the complaint pointed at the wrong thing. It now answers "read only previews a file. Use `load sales.csv as <var>` to keep it". Only an `as` in the alias position is refused, so `read book.xlsx sheet as` still previews a sheet named `as`.

### `ml` and `nn`

- `ml/mltest.RunConformance` fails an implementation whose `Classes()` returns nil, instead of crashing on it. `ml.Classifier` is a public interface that code outside this repository can implement, and the suite used to call `Len()` on the result unchecked.

### `datafetch`

- The Google Maps crawler's `Search` works again. Google stopped putting store IDs in the page it read, so it returned nothing for every query without a warning. It now reads the result list the Maps web page requests: up to 20 stores with their names in one request, instead of one extra page load per store, and a warning when nothing comes back. `GoogleMapsStores()` no longer downloads its endpoints and request headers from a GitHub repository at run time, so it needs no network access and never returns nil, and every request times out after 30 seconds. `GetReviews` logs progress at debug level instead of printing to standard output, no longer panics when `MaxWaitingInterval_Milliseconds` is exactly 1000, and treats a zero `SortBy` or `MaxWaitingInterval_Milliseconds` as its default without a warning. `GetReviews` works again too. Google refuses the review request it used to send, and Google Maps shows a signed-out visitor only five reviews, so it now reads the review pages of the review window on Google Search results: 10 reviews a page, in any of the four sort orders, with no sign-in ([#249](https://github.com/HazelnutParadise/insyra/issues/249)). `ReviewDate` is now the UTC posting date as `YYYY-MM-DD`, `Content` has line breaks instead of `<br>`, and `ReviewerState` and `ReviewerLevel` are always empty because the new pages do not carry them.
- `GoogleMapsStoreReview` has four more fields, which `GetReviews` fills and `ToDataTable` turns into columns of the same name: `ReviewID`, `Language` (the review's language code, such as `zh-Hant`, and empty for a review with only a star rating), `ReviewerReviewCount` (how many reviews the reviewer has written) and `ReviewerPhotoCount` (how many photos they have posted).

### `stats`

- `KMeans` picks distinct initial centres, as R does. On data with repeated rows a single-start run used to draw the same row twice and fail with "empty cluster" — 44 of 50 seeds in one measured case. A colliding draw is now redrawn from the distinct rows; a draw that was already distinct is untouched, so every existing seeded result is bit-identical.
- Functions taking `insyra.IDataList` no longer panic on a `nil` argument or on an implementation other than `*insyra.DataList`; the value is converted and a `nil` is reported as an ordinary error.
- `FactorAnalysisResult.RotationConverged` reports whether the rotation converged. It was always `true`: the candidate chosen among restarts never carried the flag, so `fa.Rotate` fell back to its default — a rotation stopped after one iteration at a tolerance of 1e-12 still reported convergence. The flag now describes the solution that is returned; how that solution is chosen among restarts is unchanged.
- A rotation that did not converge logs one warning per search, naming the method, the number of starts and the iteration cap, and only when the solution it returns did not converge — the case `RotationConverged` reports as `false`. `GPForth` and `GPFoblq` used to warn on every start that hit the cap, and the Varimax start a multi-start search builds warned too, so a call with `Restarts` above 1 could log several warnings and push as many entries into the global error buffer while the returned solution had converged; those runs now report at debug level only.
- `Skewness` and `Kurtosis` refuse a value they cannot read as a finite number instead of reading it as zero, which is what the `stats` documentation has always said of every numeric entry point. A blank, text, `NaN` or `Inf` cell is an error naming `sample` and the one-based row: `Skewness` of `[1, nil, 3, 4]` returned `0` and `Kurtosis` of `[1, "x", 3, 4]` returned `-1.64`. As documented, a string is refused even when it spells a number. Results on fully numeric input are unchanged.
- `SingleSampleTTest`, `TwoSampleTTest`, `SingleSampleZTest`, `TwoSampleZTest`, `FTestForVarianceEquality`, `BartlettTest`, `LeveneTest` and `CalculateMoment` refuse a cell they cannot read as a finite number, naming the series and the one-based row, which is what the `stats` documentation has always said of every numeric entry point. The tests took `n` from the list length while the mean and standard deviation skipped the unreadable cell, so `[1, 2, nil, 3]` reported t = 4.00, p = 0.028 instead of the t = 3.46, p = 0.074 of `[1, 2, 3]`: a blank turned an insignificant result significant. `CalculateMoment` read such a cell as zero, and `LeveneTest`, which already refused it, now names the row the same way. A `nil` list, typed or not, is an error instead of a panic in `SingleSampleTTest`, `SingleSampleZTest` and `CalculateMoment`. Results on fully numeric input are unchanged; clean blanks with `ClearNils` before testing.

### `csvxl`

- Fixed `AppendCsvToExcel` leaving the old sheet's cells in place when a sheet of the same name already existed: `excelize.NewSheet` returns the existing sheet, so only the cells covered by the new CSV were overwritten and the rest survived. The existing sheet is now cleared in place before the CSV is written, so no old cell or formula survives while the sheet keeps its position and its settings such as column widths, including when it is the workbook's only sheet.

Only a name made from a sheet name is checked, so a `csvNames` entry is used as given, and a sheet named `.` or `..` still converts. Each sheet is read before its CSV is created, and a write error at the final flush is returned.

### `parquet`

- Fixed `ReadColumnOptions.MaxValues` having no effect. `ReadColumn` now sums the row counts of the selected row groups from the file metadata and refuses the read before loading anything when the count exceeds the limit, which is what the field documented.
- `Write` returns the error from closing the Parquet writer instead of only logging it. The footer is written on close, so a failed close used to leave an unreadable file behind a `nil` error. Close-time errors elsewhere in the package are logged through Insyra's logger instead of the standard `log` package, so `Config.SetLogLevel` applies to them.
- Fixed `FilterWithCCL` returning only the first 1000 matching rows. The file is read in batches of 1000, and every batch after the first was appended to a copy of the result column rather than the column itself, so a 2500-row file filtered on a condition every row satisfies came back with 1000 rows and no error at all. Matching rows are now collected across the whole stream.
- A read error that arrives after the last batch is no longer traded for a partial answer. The reader's record and error channels are closed together, and the `select` in `FilterWithCCL`, `ApplyCCL` and `Stream` could pick either, so a file that failed to read part-way could return a truncated table with a nil error — and in `ApplyCCL`'s case overwrite the original file with the truncated result. All three now read the error channel before finishing. A successful streaming call also stops logging `failed to close file … file already closed`, which it printed every time.
- Reading a Parquet file written by another tool no longer turns a column type the reader did not handle into one repeated string. `getVal`'s fallback returned `arr.String()`, the string form of the whole array, ignoring the row index, so every row of such a column read back as something like `[19000 19001 19002]` with `Read` returning a nil error and the table's `Err()` nil. `parquet.Write` emits only seven Arrow types, so this was invisible on files this library wrote and hit everything else. Now `Date32`/`Date64` read as `time.Time` at UTC midnight, `Int8`/`Int16` and the four unsigned widths as their own Go types, `LargeString` as `string`, and `Decimal128`/`Decimal256` exactly, as a [go-decimal](https://github.com/TimLai666/go-decimal) `decimal.Decimal` built from the file's own unscaled integer and scale. Anything left — `List`, `Struct`, `Map`, `Time32`, `Time64`, `Duration`, `Interval` — reads as `nil` cells, and the rest of the file still reads. `Read`, `Stream` and `ReadColumn` log the reason as a warning and record it on the returned table's or list's `Err()`, as `column "tags": unsupported Arrow column type list<item: int64>; its cells were read as nil`; when several columns are affected, each is logged and `Err()` names the last. `FilterWithCCL` sees `nil` for such a column too, without recording a reason. `ReadOptions.Columns` can skip the column. A column of Arrow type `Null` reads as `nil` cells with no reason recorded, since that is all it holds. A dictionary-encoded column reads as the Go type of its values, whether the reader materialises it or, for a file that stores its Arrow schema, hands it over as an Arrow dictionary.
- A `decimal.Decimal` sorts by value rather than by the lexicographic order of its digits, so a column holding 9.5, 10.2 and 100.0 sorts in that order rather than 10.2, 100.0, 9.5. Like `time.Time`, it is not numeric to `Mean`, `Sum` or `IsNumeric`.
- A Parquet `Binary`, `LargeBinary` or `FixedSizeBinary` column reads as `[]byte`. Every row used to hold the same text, the string form of the whole array, with a nil error, so the bytes were lost and a binary column read back like a text one. Each cell now holds its own bytes, copied out of Arrow's buffer, in `Read`, `Stream` and `ReadColumn`. `Show` prints the column as hex, and JSON export writes it as base64. `Write` still writes a column of `[]byte` cells as a string column, holding Go's text for the slice such as `[65 45 48 49]`, so writing such a column back does not keep its bytes.

## v0.3.1

### Core

- Added `CSVReadOptions` together with `ReadCSV_FileWithOptions` and `ReadCSV_StringWithOptions`. Setting `RawStrings` keeps every cell as its original string and skips column-level type inference, so values like stock IDs no longer lose their leading zeros and empty cells stay `""` instead of becoming NaN. `ReadCSV_File` and `ReadCSV_String` keep their existing signatures and behavior.
- Added fitted `SimpleImputer` strategies for mean, median, mode, and constants. It remembers training-table replacements for later tables, so imputation can be used in leakage-free preprocessing pipelines; the existing in-place `FillWith*` methods are unchanged. It deliberately has no `InverseTransform` and is not an `insyra.Scaler`: imputation cannot be undone, and a method that always failed would tell a type assertion the capability was present.
- Added `Config.SetAcceleration` and `Config.GetAccelerationEnabled`. Acceleration is enabled by default; the programmatic switch controls device call sites, while `INSYRA_ACCEL_DISABLE_WGPU=1` remains the operations override and wins when both are set.
- CCL column expressions now thread recursion depth on the evaluation stack instead of doing goroutine-ID and `sync.Map` bookkeeping per AST node. On an Apple M3, the issue #191 expression measured 4.5x faster at 10k rows and 6.0x faster at 100k rows, with results, limits, and error messages unchanged.

### `isr`

- `CSV_inOpts` gains a `RawStrings` field, which `DT.From` passes through to the reader.

### `accel`

- Large `nn` 2-D float32 MatMuls now have a default-on device path through `accel.DeviceMatMul`. It preserves each output's serial `k` accumulation order, records fallback reasons through the existing `accel` report, and leaves the exact CPU path in charge when no device is available or the backend fails. `INSYRA_ACCEL_DISABLE_WGPU=1` disables the backend.
- The wgpu backend is upgraded to v0.30.35, which fixes the upstream Metal checkptr abort — `go test -race` now covers the whole device path instead of skipping it, and the race guards are removed. Device numeric parity is unchanged across the upgrade.
- `accel` now executes on real hardware. `ExecuteDataList`, `ExecuteDataTable`, and `ExecuteProjectedDataset` return the computed value per column in `ExecutionResult.Reductions`, along with measured `Transfer`, `Dispatch`, and `Readback` durations and `BytesUploaded`.
- `accel.Session` is now safe for concurrent use. Every public method is serialized behind a session lock, so several goroutines can share one session; previously concurrent `ExecuteDataList` calls raced on the cache and report state. Device submission is also serialized process-wide, because all sessions share one GPU handle.
- Added `accel.Default()`, a session shared by the process and created on first use. Discovery runs once, the resident cache is shared across operations, and `Close` on it is a no-op because no caller owns it. Importing the package still opens no device.
- Added `accel.OpSquaredDistance` with `Session.ExecuteDistances`, computing the squared Euclidean distance from every row to each query point on a GPU, and `accel.SquaredDistancesCPU` as its reference. Device results are verified bit-identical to the reference on the running platform.
- Added `accel.OpNearestQuery` with `Session.ExecuteNearestQuery` and `accel.NearestQueryCPU`, reporting the closest query point per row and its squared distance. The minimum is taken on the device, so the result grows with rows rather than with rows times queries — 13.6x over the CPU at 64 query points on an Apple M3. Ties go to the lowest query index.
- `accel` is now part of `allpkgs`, so the standard `go get .../allpkgs` install registers the GPU backend automatically. Registration is lazy — no device is probed until an accel session opens.
- GPU execution is builtin. The backend is a pure-Go WebGPU implementation ([gogpu/wgpu](https://github.com/gogpu/wgpu)) that registers itself when `accel` is initialised, so there is nothing extra to install and nothing to import for a side effect. It builds with `CGO_ENABLED=0` and reaches Metal on macOS, Vulkan on Linux and Windows, and DirectX 12 on Windows. Programs that never import `accel` compile none of it, though the gogpu modules do appear in `go list -m all`. Set `INSYRA_ACCEL_DISABLE_WGPU=1` to turn it off without changing code.
- **Breaking:** `BackendAllocator`, `RegisterBackendAllocator`, `AllocationRecord`, and `AllocatorKind` are replaced by `BackendExecutor`, `RegisterBackendExecutor`, `ExecuteRequest`/`ExecuteResponse`, and `ExecutorKind`. The old seam could not carry an operation or return a value, so no real backend could implement it.
- **Breaking:** `ExecutionResult.Allocator` and `ExecutionResult.AllocatorKind` are now `Executor` and `ExecutorKind`; `ExecutionResult.BytesMoved` is gone. It was derived from fixed per-backend constants rather than measured, so it is replaced by `BytesUploaded` and the three measured durations.
- GPU execution requires an explicit precision opt-in. WGSL has no `f64` and Apple GPUs have no double-precision hardware, so a `float64` column is not narrowed unless `WorkloadEstimate.Precision` is set to `accel.PrecisionFloat32`. Without it the workload falls back to the CPU with reason `precision-not-accepted`.
- Added fallback reasons `no-backend-executor`, `precision-not-accepted`, `dtype-not-eligible`, `shader-compile-failed`, `buffer-too-large`, `readback-timeout`, and `execution-failed`.
- A backend-reported CPU or software adapter is never treated as an acceleration device, so a host with no GPU driver falls back to the CPU instead of running a software interpreter and calling it acceleration.
- Projecting a column is much cheaper. Dataset fingerprinting no longer renders every value to text before hashing it, and `projectValues` no longer dispatches through `reflect` per element — the old path heap-allocated once per value. On a 4 Mi `float64` column, projection went from 4,194,308 allocations to 4, `ProjectDataList` from 357 ms to 43 ms, and an end-to-end GPU column sum from 354 ms to 48 ms. Fingerprints are session-local, so the different hash values are not observable across runs.
- `ExecuteDistances` and `ExecuteNearestQuery` now return the result whether or not a device ran. Previously a host with no GPU got `Accelerated: false`, the reason `no-accelerator`, and an empty slice, leaving every caller to notice and call the CPU reference itself. The same applies when a device is present but fails, times out, or exceeds a buffer limit. `Accelerated` and `FallbackReason` still report where the work ran, so nothing becomes less observable. A request refused on its own terms — `precision-not-accepted`, `dtype-not-eligible`, `workload-unsupported` — still returns nothing, because computing it on the CPU would deliver exactly what the caller declined. Strict GPU mode still returns an error rather than a CPU result.
- Added `accel.OpNearestShortlist` and `Session.ExecuteNearestExact`, which returns the M nearest query points per row as exact `float64` values while still using a GPU for most of the work. The device ranks in single precision and returns a shortlist per row plus the distance of the best candidate it discarded; the host recomputes that shortlist in `float64` and decides, falling back to every query point for the rows where single precision could not separate the candidates. The answer equals `accel.NearestExactCPU` exactly, so no precision opt-in is required. Measured on an Apple M3 over 200,000 rows against a host using all eight cores: 2.5x at 16 dimensions and 3.4x at 64, both with 1024 query points, and slower than the host below roughly 2048 distance evaluations per row — where the runtime declines the device and reports `workload-not-profitable`. `ExactNearestResult.Rechecked` reports how many rows took the full path.
- The host side of `ExecuteNearestExact` now uses every core. Both the no-device path and the verification of a device shortlist are split across `GOMAXPROCS` above a work threshold; below it they stay on one core. On 200,000 rows by 16 dimensions with 1024 query points the path taken by a machine with no GPU went from 1.575 s to 306 ms. The device shortlist is also read row-major rather than candidate-major, so verifying one row no longer strides across the whole array.
- `ExecuteNearestExact` no longer panics when asked for nine or more neighbours on a host with a GPU. The shortlist width was clamped to the device's eight slots while the decision still indexed position `m-1`; the device is now skipped for requests it cannot serve, and the host answers instead. It also no longer trusts a shortlist whose single-precision distances overflowed to infinity — the ordering carries no information in that case, and the boundary test passed for the wrong reason. The error bound used to decide whether a shortlist can be trusted was widened to account for the rounding of the difference itself and for squared terms below the smallest normal `float32`.
- **Breaking:** `OpSum`, `OpSquaredDistance` and `OpNearestQuery` are removed, together with `ExecuteDataList`, `ExecuteDataTable`, `ExecuteProjectedDataset`, `ExecuteDistances`, `ExecuteNearestQuery`, `SquaredDistancesCPU`, `NearestQueryCPU`, their WGSL kernels, and the `accel run <var>` CLI command. Each was measured against a host using all its cores and lost: the column sum runs at 0.7x because it moves one value per element and adds it once; the distance matrix reads back a result that grows with rows times query points; and the single-precision nearest query answers in `f32`, which the `float64` callers it was built for cannot use. `ExecuteNearestExact` supersedes the last of these and returns the exact `float64` answer. None of the removed surface appeared in a release. `accel devices`, `accel cache` and `accel plan` are unaffected.
- Oversized `ExecuteNearestExact` submissions now run as sequential 16,000-row device chunks and merge in input order instead of losing the device to a readback timeout. The exact `float64` CPU decision is unchanged, submissions at or below the measured bound keep the single-submission path, and `ExecutionResult.Chunks` reports the number of device submissions.
- Added hard device selection for accel sessions. `INSYRA_ACCEL_DEVICES` masks devices at discovery and `Config.Devices` allowlists a session; the eligible set is their intersection, while `PreferredDevices` remains a soft ordering within it. IDs and zero-based discovery indices are accepted, unmatched entries appear in `Report.UnmatchedDeviceSelectors`, and empty bounds fall back with `device-selection-empty` or error in strict mode.
- Added per-assignment accel dispatch with `single`, `auto` (default), and `forced` shard strategies. `auto` uses the recorded 32k/8k saturation floors, assignments report placement, wall time, chunks, and fallback, and a failed assignment falls back only its own rows. Correctness is verified bit-identically on single-device hardware; multi-GPU wall-clock measurement is unmeasured.
- Acceleration now logs one session-scoped info line at first device use and first qualifying fallback, with per-execution placement at debug level. The root `Config` log level controls the output. `Config.SetAcceleration` also logs one info line per actual state transition, so a mid-run toggle is visible at the moment it happens.

### `stats`

- `PCA` returns an error instead of panicking on a table with no columns. The shape guard existed but sat 34 lines below the `mat.NewDense` call it was meant to protect, so a zero-column table crashed the caller with `mat: zero length in matrix dimension`.

- Added `Predict` to linear, polynomial, exponential, and logarithmic regression results. It follows the GLM prediction signature and returns response-scale point predictions for new data, with predictor-count and row-length validation. R's standard errors and prediction intervals remain outside the current API.
- Added `KMeansResult.Assign` to apply fitted centers to new observations and return the one-based center index with its squared Euclidean distance.
- `PCAResult` now returns the fitted per-column centering and scaling parameters, together with the training scores, so callers can project new observations with the same decomposition.
- Logistic and Poisson regression results now expose the fitted `Link`, matching `GLMResult.Link`, so callers can reproduce response predictions from linear predictors outside `stats`.
- Passing a nil table to a clustering or decomposition entry point now returns an error instead of panicking. `KMeans`, `DBSCAN`, `Silhouette`, `HierarchicalAgglomerative`, `PCA` and `KMeansResult.Assign` all dereferenced the table before validating it, so both a nil interface and a typed nil crashed the caller.
- **BREAKING**: a value that cannot be read as a finite number is now refused instead of being treated as zero. This affects `LinearRegression`, `PolynomialRegression`, `ExponentialRegression`, `LogarithmicRegression`, `PoissonRegression`, `GLM`, `Correlation`, `Covariance`, `CorrelationMatrix` and `CorrelationAnalysis`, in the target as well as the predictors. These routed every value through a conversion with no failure channel, so a missing value, a blank or text silently became `0` — one blank among six observations moved a Pearson coefficient from 0.9992 to 0.9879 with no error and nothing downstream able to tell. Clustering, PCA and KNN already refused; factor analysis already deleted the observation. The error names the series and the row, and `Docs/stats.md` now states each family's treatment.
- Added `RidgeRegression` and `LassoRegression`, using scikit-learn's objectives exactly — L2 penalty `||y − Xβ||² + α·||β||²` solved in closed form, L1 penalty `(1/2n)·||y − Xβ||² + α·||β||₁` by coordinate descent — with the intercept unpenalized and no standardisation, both verified coefficient-for-coefficient against scikit-learn. Ridge handles collinear predictors that make `LinearRegression` fail; lasso drives priced-out coefficients to exactly zero and reports non-convergence instead of hiding it. Neither result carries standard errors, t or p values, because classical inference does not apply to penalized estimates. scikit-learn rather than R's glmnet is the reference: glmnet standardises by default and scales its penalty differently, so it computes different coefficients from the same data.
- Added `WeightedLinearRegression` (WLS): weighted normal equations with exact classical inference — coefficients, standard errors, t and p values, weighted R² and predictions all verified field-for-field against statsmodels' `WLS`. Weights must be strictly positive; a zero weight is refused rather than guessed into exclusion semantics, because references disagree on the degrees of freedom and standard errors matching nobody would be the result.
- Auto-algorithm KNN can use the GPU: blank-import `accel/knnbridge` and profitable shapes route through the exact-nearest device operation, whose answers the CPU recomputes in `float64` — device results are identical to brute force, index for index, verified on hardware, and the win is measured in the wiring's own direction (1.4x at 2k test rows to 3.7x at 10k, on 100k×32 against all cores). Explicitly named algorithms, `k > 7`, small shapes and machines without a device all run the CPU path unchanged, and without the import `stats` carries no accelerator dependency.
- CPU auto-algorithm KNN now probes a deterministic sample of the caller's test rows before accepting a ball tree. When pruning examines too much of the training set, it falls back to exact brute force; explicitly named algorithms remain honored, and results are bit-identical because the probe only selects the exact search path.

### `nn`

- Added `Sequential.Fit` as a deterministic training front door with explicit optimizer and loss selectors, seeded `rng.Perm` minibatches, optional `Predict`-based validation, callback progress, and one root-logger info line per epoch. The Fit path reproduces the documented tape loop's loss sequence digit-for-digit; schedules, early stopping, checkpointing, and `DataTable` integration remain outside v1.
- Added the resize operator wave, scoped by inventory of two more published checkpoints: `Resize` (nearest and linear, scales or sizes, asymmetric and pytorch_half_pixel coordinate modes), opset-9 `Upsample`, `Floor`, `InstanceNormalization`, and reflect-mode `Pad`. FCN-ResNet50 (semantic segmentation) and mosaic-9 (fast neural style) now run unmodified and match `onnxruntime`; ConvTranspose and TopK stay unbuilt because no target model needs them.
- Large 2-D float32 MatMuls are now device-on by default without a blank import. Only products at or above the measured 16Mi MAC floor consult the device; batched or smaller products remain on the byte-identical CPU path. `INSYRA_ACCEL_DISABLE_WGPU=1` and `nn.RegisterDeviceMatMul(nil)` restore CPU-only execution. Measured on the 8-core M3 / Metal, the device result is bit-identical to the CPU's at every ladder rung, wins from 1.35x at the floor to 52x at 4096-square, and drops the measured encoder layer from about 0.9s all-core CPU to 234ms.
- Extended the autodiff tape with CNN VJPs for 2-D Conv, MaxPool, AveragePool, GlobalAveragePool, and inference-mode BatchNormalization. Grouped Conv, asymmetric padding, strides, pooling denominator semantics, and all three BatchNormalization gradients are covered by finite differences; a deterministic CNN now matches PyTorch through one Adam step.
- Added a `Layer` and `Sequential` surface over the autodiff tape, with eager dimension checks, seeded He-initialized `Dense`, activation, `Dropout`, `Flatten`, and `Func` layers. `Predict` structurally skips training-only layers, names parameters like torch `nn.Sequential`, and loads torch Linear SafeTensors with the `[out,in]` to `[in,out]` boundary transpose. The Sequential MNIST proof reproduces mean losses `0.350281` and `0.163855` and reaches `95.84%` accuracy after two epochs.
- Completed the trainable layer catalog with `Conv2D`, `MaxPool2D`, `AvgPool2D`, `GlobalAvgPool`, training/eval `BatchNorm2D`, `LayerNorm`, and `Embedding`. Training BatchNorm matches torch's biased normalization, unbiased running variance update, and three-term gradient; Embedding scatter-adds repeated indices. Torch state-dict loading accepts convolution and normalization buffers, and the gated CNN catalog proof reaches `97.27%` on MNIST in two epochs using a documented 30,000-row subset.
- Added deterministic `SaveSafeTensors`, `Sequential.SaveWeights`, and `Sequential.ExportONNX`. Saved state dicts use torch names, include BatchNorm running statistics, and reverse the Dense transpose; ONNX exports supported inference layers, omits Dropout, and refuses Func or Embedding by layer position. Trained MLP and CNN exports round-trip through `nn` exactly and through `onnxruntime` within float32 tolerance.
- Added fused mean `MSELoss` and `BCEWithLogitsLoss` tape operations, per-parameter `SGDMomentum`, `CosineAnnealingLR`, and global-norm `ClipGradNorm`. A six-step BCE training recipe matches PyTorch at every step for learning rate, loss, pre-clip norm, and all parameters.
- Added torch-compatible `MultiHeadAttention(embed, heads)` and `Residual(layers...)` layers. Mask-free batch-first self-attention composes existing tape operations, nested layer state names round-trip through SafeTensors with torch projection transposes, and a layer-built encoder matches PyTorch through one AdamW step. ONNX export refuses both composite layers by position and kind.
- Added detector-oriented ONNX inference support: `LeakyRelu`, `Exp`, `Ceil`, `Round`, `Tile`, `ReduceMin`, batched `NonMaxSuppression`, and `Loop` with validated GraphProto bodies, child scopes, loop-carried values, and scan outputs. One-op and synthetic Loop parity pass against `onnxruntime`, and gated tiny-YOLOv3 parity matches exact selection indices and f32 boxes and scores.

### `ml`

- ONNX export now produces models an independent runtime accepts. Two defects had survived because the round-trip verification requires `python3` with `onnxruntime` and had silently skipped on every machine it ran on. Every non-string attribute carried a stray empty string data field, which onnxruntime rejects as an invalid graph before running anything; and tree nodes were written deepest-leaf-first, while the runtime treats each tree's first array entry as its root — so it walked one node and refused the model. Nodes are now written root-first, and the round-trip — linear, logistic, both trees, and a pipeline — passes against onnxruntime.

- `mltest.RunConformance` now uses the training labels it is given. It took them and discarded them, so a caller passed a value nothing was checked against. For a `Classifier` it now verifies that `Classes()` accounts for every label the model was fitted on — a class set omitting one describes a label the model can never predict.

- Added `ml.Clusterer`, an optional interface a clustering model implements to say its predictions are group assignments rather than measurements, reporting how many groups the fit converged on. A regression metric is now refused against one. Previously `KMeansModel` was neither a `Classifier` nor a continuous predictor, so nothing stopped `RMSE` from scoring its cluster ids and returning an arithmetically correct number about nothing.

- A metric written outside the package can now say what input it needs. `ClassLabelMetric` and `ProbabilityMetric` are exported, so a caller-written metric can request class labels or probabilities the way the built-in ones do. Previously the routing keyed off unexported marker interfaces, so an external metric could never request probabilities — it silently received the model's predictions instead, with `Prediction.Probabilities` nil and no error. Both interfaces are now read rather than merely detected: implementing one and answering `false` is the same as not implementing it. `Prediction`'s fields document which are populated when.

- `mltest.RunConformance` now checks the probability ordering by value, not only by column name. It compared column names against class names, which a model that derives its names from its own `Classes()` list satisfies by construction — so a model whose probability values sat under the wrong labels passed a check written to catch exactly that. For every row, the class `Predict` returns must now be the class whose column holds the largest probability. Its renamed-column check was also strengthened: the renamed name was a superstring of the original, so an error naming only the incoming column satisfied it.

- `ROCAUC` now refuses a true label that belongs to neither probability class, instead of treating it as negative. It previously reported confident discrimination — an AUC of 1 with a nil error — over data it had not understood, while `LogLoss` refused the identical input. The two metrics no longer disagree.

- Added a common estimator and transformer protocol over the fitted models already provided by `stats`, with name-based feature binding, optional probability capabilities, PCA transformation, KNN wrappers, and `ml/mltest` conformance checks.
- Added `ml.NewPipeline` and `ml.NewColumnTransformer` for fitting preprocessing and a model together, scoping transformers to named columns, and reusing the fitted result without preprocessing leakage.
- Added seeded k-fold and stratified splitting, estimator cross-validation with one score per fold, and classification and regression metrics including accuracy, log loss, ROC AUC, confusion matrices, RMSE, MAE, and R².
- Added deterministic histogram decision-tree classification and regression with quantile-binned numeric features, categorical subset splits, learned missing-value routing, bounded growth, class probabilities, and feature importances.
- Hardened the `ml` protocol and pipelines: unnamed feature schemas and unsupported regression offsets are rejected, logistic models distinguish labels from probabilities, fitted pipelines preserve supported capabilities and input order, and decision-tree regression retains precision for small targets.
- Added dependency-free ONNX export for linear and logistic models, decision trees, and fitted pipelines with supported scalers and encoders. Unsupported models are refused before writing, and the export tests use an independent `onnxruntime` round trip when it is available.
- `Score` evaluates a fitted model on held-out data with a supplied metric, without refitting. It runs the same compatibility check and prediction assembly as `CrossValidate`, so a metric needing probabilities — or needing class labels from a model that reports probabilities — is served identically either way. scikit-learn attaches a default metric to the estimator class; Go has nowhere to hang that, so the metric is an argument.
- **BREAKING** for metrics defined outside the package: `Metric` gains `Direction`, declaring whether a larger or smaller score is better. `CrossValidationResult` carries it, and `Better` compares two results by it. Without this a caller comparing two means picked the worse model half the time, since half the built-in metrics improve as their score rises and half as it falls. A metric that returns a rankable score while declaring `NoDirection` is refused rather than defaulted.
- Fitted pipelines report `TransformedFeatureNames`, the columns the final estimator was fitted on after every step ran. A pipeline over two columns that encodes one into three reported two feature names and four importances, with nothing to align them. The conformance helper now requires a model's importance count to match its feature-name count.
- Added `PrecisionMetric`, `RecallMetric` and `F1Metric` with macro, micro, weighted and binary averaging, plus the `Precision`, `Recall` and `F1` direct helpers, all verified against scikit-learn's `precision_recall_fscore_support`. The default averaging is macro rather than scikit-learn's binary-with-`pos_label=1`, which over arbitrary labels is a guess; binary averaging requires the positive class to be named, because unlike ROC AUC these scores change with which class is positive. A never-predicted class contributes precision 0, matching `zero_division=0`.
- Added `FitRidgeRegression` and `FitLassoRegression`, wrapping the new `stats` estimators into the estimator protocol with name-based feature binding, conformance-checked.
- `GridSearch` cross-validates named candidate estimators on identical folds — drawing and reporting one seed when none is supplied, so the comparison is fair and reproducible — ranks them by the metric's declared direction with ties keeping the earliest candidate, and returns the winner refitted on the full data. The grid arrives already expanded as named estimators, because parameter-grid expansion is the `clone()` reflection this protocol deliberately does not have.
- Added random forests (`FitRandomForestClassifier`, `FitRandomForestRegressor`): bootstrap resampling expressed as row multisets over one shared preparation, per-split feature subsampling (√p for classification, all p for regression), probability-averaged prediction, and importances as the renormalized mean of the per-tree importances. Trees fit in parallel but every draw derives from one seed, reported on the model when drawn, so the same seed always reproduces the same forest. Classes are collected from the full target before resampling, so a bootstrap sample missing a class cannot misalign probability columns.
- Added gradient boosting (`FitGradientBoostingRegressor`, `FitGradientBoostingClassifier`): squared-loss residual fitting for regression, binary logistic loss with Newton-step leaf values for classification, scikit-learn's defaults, early stop on zero residuals with the ran-stage count reported. Multiclass targets are refused with the limit named rather than approximated.
- Added `FitWeightedLinearRegression(x, y, weights)`. The weights apply to that fit only: `CrossValidate` has no weights channel, so the limitation is documented rather than silently misaligned.
- `CrossValidateWeighted` routes sample weights to fitting: each fold's estimator receives its training rows' weights, subset with the same indices that built the fold, so alignment holds by construction. `Estimator` gains an optional `FitWeighted` — everything that does not mention weights is unchanged. Held-out scoring stays unweighted, matching scikit-learn's default; an estimator without `FitWeighted` is refused rather than silently fitted unweighted.
- ONNX export covers the new families: ridge, lasso and WLS through the linear-regressor path, and both forests and both boosters as multi-tree ensembles — a forest's leaves scaled by 1/T so the runtime's sum is the average, boosting with the learning rate baked into leaf weights and the prior as base value. Binary classifiers use the runtime's single-score convention: written with both classes' weights, the probabilities came back exactly right while every label came back 1, so two-class ensembles carry one score per leaf and the runtime computes the complement and the half-threshold label. All seven families pass the independent onnxruntime round trip.
- Decision trees gained `ExactSplits`: every midpoint between adjacent distinct numeric values is a split candidate — scikit-learn's CART search — alongside the default histogram search. The split criteria already matched (Gini, variance), so the exact tree is verified prediction-for-prediction against scikit-learn: classification labels exact on a probe grid, regression within single-precision tolerance. Histogram stays the default for its O(MaxBins) cost; combining the two options is refused, and ensembles inherit the choice.
- Exported logistic models now carry two coefficient rows (skl2onnx's binary convention), fixing the probabilities output under onnxruntime: the single-row form relied on the runtime applying the LOGISTIC transform on its binary path, and onnxruntime does not — it returned the raw decision score as the probability, unnoticed while the round trip compared labels only. Found by `nn`'s double-reference round trip; labels were always correct.
