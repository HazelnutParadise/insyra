# Changelog

Changes that affect people using Insyra, grouped by package the same way release notes are. `## Unreleased` holds what will go into the next release.

v0.3.0 and everything before it is not repeated here — see [GitHub Releases](https://github.com/HazelnutParadise/insyra/releases).

## Unreleased

### Core
- **BREAKING**: `DataList` numeric transforms no longer rewrite part of a list before failing, and no longer read an unreadable cell as `0`. `Normalize`, `Standardize`, `ClearOutliers`, `Difference`, and `FillNaNWithMean` scan the whole list first; a cell that is neither numeric, `nil`, nor `NaN` sets `Err()` (naming the row) and leaves every cell as it was, where previously `[1, "x", 3].Normalize()` returned `nil` after overwriting the first cell with `0`. `nil` and `NaN` cells pass through unchanged and are excluded from the mean, standard deviation, min, and max the transform uses, so `ClearOutliers` on a list with blanks now checks every numeric cell instead of stopping at the first blank. `Rank`, `ExponentialSmoothing`, `DoubleExponentialSmoothing`, and the six `*Interpolation` methods stop reading through `ToF64Slice`: `Rank` gives `nil`/`NaN` cells a `NaN` rank without consuming a rank position and fails on any other non-numeric cell (`[3, "b", 1].Rank()` used to rank `"b"` first as `0`); the smoothing and interpolation methods require a fully numeric series and fail otherwise. Results on fully numeric input are unchanged.
- `DataTable` results no longer share memory with the table they came from: `Data()` and `ToMap()` return copies, and every `Filter*` result owns its columns and row names, so editing a filtered table no longer edits the source. `ChangeRowName` onto a name another row already has suffixes the renamed row instead of silently stripping the other row's name. `DropColsContainNumber`/`DropRowsContainNumber` now also drop a column or row holding a named numeric type such as `time.Duration`, or a decimal, which v0.3.3 kept. `ToCSV` writes `time.Time` cells as RFC 3339 so `ParseDates` reads them back. `AddColUsingCCL`, `EditColByIndexUsingCCL`, `EditColByNameUsingCCL` and `ExecuteCCL` return the receiver rather than `nil` after a recovered panic.
- The error hook installed by `SetDefaultErrHandlingFunc` skips a call that finds its queue of 1,024 full, where v0.3.3 delivered such a call on a goroutine of its own. The message is still kept in the error buffer, and the first skipped call prints one warning through the standard logger.
- `DataList.IsEqualTo` and `IsTheSameAs` treat two `NaN` cells as equal, so a list now equals its own clone. In v0.3.3 a scalar `NaN` cell never equalled another.
- CCL: an Excel-style reference past the last column (`E` on a three-column table) is an error instead of a column of `nil`; a date difference compares and divides as seconds, so `(A - B) > 0` no longer reads as `false`; `SUM`, `AVG`, `MEDIAN`, `STDEV`, `STDEVP`, `VAR` and `VARP` skip `NaN`, as `MAX` and `MIN` already did; `REPEAT` refuses a negative count, including a fraction such as `-0.5` that v0.3.3 read as `0`, and a result longer than 64 MiB.
- `ToCSV` and `ToJSON` write through a temporary file that is renamed into place, so a failed write never leaves a truncated file.
- `AtomicDoAll` called from inside an `AtomicDo` on one of its instances no longer deadlocks against a goroutine doing the mirror image: it runs the callback inline without locking the others, the same rule nested `AtomicDo` follows.
- **BREAKING**: insyra no longer ends your program. `LogFatal` records the failure and returns instead of calling `os.Exit(1)`, so a failed chart save, a missing GLPK install or an unreadable file leaves your program running. Opt into the old fail-fast behaviour with `Config.SetPanicOnError(true)`, which panics — recoverably, never `os.Exit` — with an `*ErrorInfo` on any recorded error. `SetDontPanic`/`GetDontPanicStatus` still work as the inverse of the new switch and are **Deprecated**; they will be removed in the release after next.
- Added `LogLevelError` between Warning and Fatal, and `LogError`. Everything recorded on an instance's `Err()` now uses Error level, so Warning goes back to meaning "done, but worth noticing".
- **BREAKING**: `Err()` on `DataList` and `DataTable` is now **sticky**. It keeps the *first* failure until `ClearErr()` or `PopErr()`, so one check at the end of a chain reports the root cause instead of the last symptom. `SetErr` no longer replaces an error that is already recorded, as it did in v0.3.3.
- **BREAKING**: searching for a value and not finding it no longer sets `Err()`. `FindFirst`, `FindLast`, `FindAll`, `Count` and the statistics over an empty list log at Warning and leave `Err()` alone, so a sticky error cannot be filled in by ordinary questions. Addressing something that is not there — an out-of-range index, `GetColByName` for a column that does not exist — is still recorded, because the only other signal is a bare `nil`.
- **BREAKING**: `DataList` transforms never return `nil`. `Normalize`, `MovingAverage`, `WeightedMovingAverage`, `ExponentialSmoothing`, `DoubleExponentialSmoothing`, `MovingStdev`, `Difference`, `Diff`, `PctChange` and `Rank` return an empty, usable list carrying the error (the receiver records it too), so `dl.MovingAverage(0).Sort()` no longer panics on a nil dereference. Lookups such as `GetColByName` still return `nil` when the target is absent; a `result == nil` check on one of the transforms above will no longer fire, so switch it to `result.PopErr()`.
- `Rank` compares integers exactly, as `Sort` has since v0.3.3: it orders and detects ties on the original cells rather than `float64` copies, so two `int64` values above 2^53 no longer share a rank.
- **BREAKING**: reading a CSV in an encoding insyra cannot decode is now an error naming the supported encodings, instead of copying the raw bytes into the table as cells that are not valid UTF-8. That covers the core CSV readers and `csvxl`'s `CsvToExcel`, `AppendCsvToExcel` and `EachCsvToOneExcel`, which still read such a file undecoded in v0.3.3, and a file the auto-detector identifies as IBM420 or IBM424, which nothing decodes.
- **BREAKING**: an encoding name is looked up in one table, with case and separators ignored. v0.3.3 also accepted any name containing `utf8`, `big5`, `gb` or `utf16`; that rule is gone, so a name such as `utf8mb4` is now refused. The aliases people use are in the table: `utf-8-sig` and `utf-8-bom` read as UTF-8 with the leading byte-order mark dropped, `big5-hkscs`, `csbig5`, `cn-big5` and `x-x-big5` as Big5, and `x-gbk`, `gb_2312-80`, `csgb2312`, `csiso58gb231280`, `chinese` and `iso-ir-58` as GBK.
- When the encoding detector cannot name a charset, which happens on a very short sample, `DetectEncoding` logs a warning and assumes UTF-8 instead of failing the whole read.
- CSV output guards against formula injection by default: text starting with `=`, `+`, `-` or `@` that is not just a number is written with a leading single quote, so a spreadsheet opening the file shows it as text instead of running it. Numbers, and text such as `-5` or `+886912345678`, are never changed. `CSVWriteOptions{AllowFormulas: true}` writes the text exactly, for a file read back by a program; the CLI's `save` takes `allowformulas true`. **BREAKING (output)**: `ToCSV` used to write such text unchanged unless `SanitizeFormulas` was set. `SanitizeFormulas` now has no effect and is **Deprecated**; remove it.
- **BREAKING**: CCL evaluates only what it needs to, and refuses an expression it cannot read the way it is written. `&&`, `||` and `CASE` short-circuit like `IF` already did, so `B != 0 && A / B > 1` returns false on a zero row instead of reporting the division by zero the guard exists to prevent. Function arguments must be separated by exactly one comma: `SUM(A B)` used to be accepted and quietly summed both columns, and a trailing comma was ignored. `&` now binds looser than `+` and `-`, as in Excel, so `'a' & 1 + 2` is `"a3"` instead of an error (and `'1' & '2' + 3` is `"15"` rather than `15`). `Docs/CCL.md` now carries the full precedence table, including the two surprises: `-2^2` is `4` and `2^3^2` is `64`.
- **BREAKING**: CCL no longer produces a value for an operation it cannot perform. Two strings compare as text: `'abc' < 'abd'` and `'abc' > 'abd'` were both false, so text columns had no ordering at all. A blank string, a date string or a date compared with a number using `>`, `<`, `>=` or `<=` is now an error like any other word, where v0.3.3 answered `false`, so `A > 0` over a date column and `A > 5` over a column with a blank in it now fail. `nil` concatenates as the empty string rather than Go's `"<nil>"` placeholder, matching `UPPER(nil) & 'x'`, which already gave `"x"`. A column range used on its own resolves against the current row, the same way a bare `A` already means `A.#`: `AddColUsingCCL("r", "A:B")` gives each cell that row's A and B values instead of an internal `ccl.ColumnRange` struct. `LAG` and `LEAD` accept a whole row, so `LAG(@, 1)` gives every row the one before it rather than the whole flattened table shifted by one; the sequence functions that do arithmetic still refuse a row, and a bare row range (`1:2`) is still an error, now saying to attach it to a column. `AND()` and `OR()` require at least two arguments; `AND()` used to return `true` and `OR()` `false`. Row indices, range bounds and rolling windows must be whole numbers: `A.(1.7)` read row 1, `ROLLING_MEAN(A, 2.9)` used a window of 2, and a `NaN` index read row 0 on arm64 but errored on amd64. `1 && 0` and `'yes' && true` still work; the docs claimed they were errors and now carry the coercion table the evaluator actually uses.
- **BREAKING**: a number written as text follows one rule everywhere insyra writes text for output, the rule `ToJSON` already followed. Go's default formatting switches to scientific notation at one million, so a revenue of 1,500,000 came out of CCL as `Revenue: 1.5e+06`, `ToCSV` wrote `1.5e+06`, and `ToStringSlice` returned it, while `ToJSON` wrote `1500000`. Now a value from 0.000001 up to (not including) 1e21 is written as a plain decimal (`1500000`, `0.00001`), and anything outside keeps exactly the exponent form it had (`1e-07`, `1e+21`). Read back, every number is the same value. Column names generated by `OneHotEncode` and `Pivot` change the same way, so `price_1.5e+06` becomes `price_1500000` and code that looks a column up by its old name stops finding it. A float category that now renders the same as an `int` or string category is rejected at fit time, the way `int(1)` and `float64(1)` already were. `nil` categories keep the name `<nil>`; sorting and `Show`'s terminal display are unchanged.
- **BREAKING**: `AtomicDoAll` takes `...Lockable` instead of `...any`. It used to accept anything, log a warning for a value it could not lock, and run the callback with that value unlocked, so a caller who passed the wrong thing believed they were protected and were not. `*DataList`, `*DataTable` and the `isr` wrappers satisfy `Lockable`; anything else is now a compile error, and a slice built as `[]any` must become `[]insyra.Lockable`.
- **BREAKING**: `ExecuteCCL` is all or nothing. A script that failed on its third statement used to leave the first two applied, with nothing to say the table was half-changed. The script now runs against a private copy of the table and is written back only when every statement succeeds; `Err()` names the statement that failed.
- The encoders key an integer category by its value, as searching and counting have since v0.3.3: `OrdinalEncode` with `Order: []any{1, 2, 3}` now matches a CSV column instead of failing, an encoder fitted on `int` data transforms `int64` data, and `int(1)` and `int64(1)` in one column are one category.
- CCL refuses a `DATEADD` shift of more than 2,147,483,647 days, months or years, and a `LAG`, `LEAD` or `ROLLING_*` shift or window outside the same range. v0.3.3 accepted either up to the `int64` range.
- **BREAKING**: the date-format patterns taken by `mkt.RFM`, `mkt.CustomerActivityIndex` and `plot.CreateKlineChart` are read by a scanner instead of a sequence of replacements over the whole string. A run of one letter is one token, so `MMM` is a short month name (it used to become `011`) and `MMMM` a full one, and `A`/`a` gives AM/PM. Literal letters now need square brackets — `"[Date]: YYYY"` — because an unbracketed `D` is a day token; before this change `"Date: YYYY"` came out as `"2ate: 2006"`, so no pattern with a literal word worked either way. `hh` and `h` still mean the 24-hour layout.
- Excel reads now pass excelize an unzip limit of 512 MB instead of accepting its 16 GB default, so a small file that decompresses into more memory than the host has is refused rather than read. `insyra.ExcelReadOptions` is exported so `csvxl` applies the same limit.
- `ToJSON` exports a value that implements `fmt.Stringer`, but neither `json.Marshaler` nor `encoding.TextMarshaler`, as its text. It used to hand the raw value to the marshaller, which writes `{}` for a struct whose fields are unexported, so a Parquet decimal column exported as `{}`. A value that implements either marshaller interface is untouched, so a `time.Time` keeps its RFC 3339 form.
- **BREAKING**: `GroupBy`, `Pivot` and `Merge` no longer merge distinct values that happened to print alike. The key encoder's fallback was `%T:%v`, which does not descend, so `[]any{1}` and `[]any{"1"}` produced the same key and the integer and the string became one group. The encoder now descends into slices, arrays, maps and structs, writing a map in encoded-key order so the result does not depend on iteration order, and stopping at depth 64 because a self-referential value would otherwise overflow the stack — a fatal error in Go that `recover` cannot catch. Keys for ordinary scalars are unchanged byte for byte.
- Fixed `Counter` making one unreachable entry per `NaN`. A `NaN` is comparable to Go but is never equal to itself, so every `counter[NaN]++` created a new key nobody could look up: a column with three `NaN`s reported three counts of one, while `Count` correctly said 3. All the `NaN`s in a column are now one entry with the right count, read with `counter[insyra.ToMapKey(math.NaN())]`. The same applies to an array or struct holding a `NaN`, which is equally unequal to itself. `counter[math.NaN()]` still returns 0, as it always did and always must — a Go map cannot match a `NaN` key.
- **BREAKING**: a fixed-point decimal in a cell is a number. `Mean`, `Sum`, `Describe`, `stats` and every other numeric path read it, where they used to answer `NaN` with no error — which is what a column of money did, since `finance.ScheduleTable` and a Parquet `Decimal128` column both hold decimals. `IsNumeric` agrees, because a value that is a number to one half of the library and unreadable to the other is the split v0.3.3 already closed for named numeric types such as `time.Duration`. A decimal also sorts among numbers now rather than in a group after strings, so a mixed column interleaves by value; two decimals still compare exactly, through the decimal's own comparison, so a difference beyond `float64`'s 16 significant digits is still seen. A value counts as a decimal by shape — it reports its own text and its scale, and that text parses as a number — so `internal/utils`, which every value passes through, does not depend on any one decimal package and any library of that shape works.
- **BREAKING**: Insyra now requires Go 1.26; the `go` directive in `go.mod` is `1.26.8`. The `lp` package's new default solver, [go-milp](https://github.com/daniel-sullivan/go-milp), needs Go 1.26. With Go 1.21 or newer, the `go` command downloads the 1.26.8 toolchain automatically unless `GOTOOLCHAIN=local` is set. The 0.3.x line stays on Go 1.25.
- **BREAKING**: CCL reads a bare word as an Excel-style column index and nothing else, on both sides of an assignment. `qty_1 * 2` and `price = A` used to fall through to the column-name map whenever the word could not be read as column letters, so whether a name worked depended on it containing a digit or an underscore, while `price * 2` never worked. Both forms are now errors, and the error says how to write what you meant: on a table with a column named `price`, `price * 2` reports that `price` reads as column index PRICE, past the last column, and that the column named `price` is written `['price']`. `['price']` and `['price'] = ...` are unchanged, and were always the documented way to refer to a column by name. A bracketed index whose contents are not column letters, such as `[qty_1]`, now fails when the expression is compiled, with the same message, instead of on row 0.
- **BREAKING**: every parameter and config field that picks a column now takes one selector, and only these three forms: a `string` is an Excel-style index (`"A"`, `"B"`, ... `"AA"`), `insyra.Name("price")` is a column name compared exactly, and an `int` is a 0-based position counting from the end when negative. Four different rules used to be in the library at once — `GetCol` read an index and then quietly retried the string uppercased as a name, `GroupBy`, `Pivot`, `Unpivot`, `Resample`, the window `*Col` methods, the encoders, the scalers and the fill family read a name first and an index second, `DataTableSortConfig` carried three fields with a precedence rule, and `mkt`'s configs carried eight `XxxColIndex`/`XxxColName` pairs. **A bare string is never a name now**, so `GroupBy("revenue")`, `CumSumCol("revenue")`, `StandardScale("age")`, `FillWithMean("value")`, `PivotConfig{Values: "sales"}` and `Resample("ts", ...)` become `insyra.Name(...)`; most such calls fail loudly, because a name rarely decodes to an in-range index, and the failure says which `Name(...)` to write when the table has a column of that name. `DataTableSortConfig`'s `ColumnIndex`/`ColumnName`/`ColumnNumber` collapse into one `Col`, and `mkt`'s pairs into one field each (`CustomerIDCol`, `TradingDayCol`, `AmountCol`, `OrderIDCol`, `ProductIDCol`). `GetCol`, `UpdateCol`, `SetColToRowNames` and the four `Replace*InCol` methods keep explicit spellings beside the generic one, now complete: `GetColByIndex`, `UpdateColByIndex`, `UpdateColByName`, `SetColToRowNamesByName`, `ReplaceInColByName`, `ReplaceNaNsInColByName`, `ReplaceNilsInColByName` and `ReplaceNaNsAndNilsInColByName` are new. `isr.Name` is now the same type as `insyra.Name`, so a selector built in either package works in both. Column names take no part in resolving a selector: they only shape the failure, and a column named like the index you gave keeps a warning naming both readings while the index still wins.
- **BREAKING**: `ReadSQLStream` returns `iter.Seq2[*DataTable, error]`, used as `for dt, err := range insyra.ReadSQLStream(ctx, db, "orders")`, and `ReadSQLChunk` is removed. The channel version leaked a goroutine and a database connection whenever a caller left the loop early, **even when it cancelled the context as the documentation said to**: the reader's cancellation branch sent the context's error on a channel nobody was reading any more and waited there for the rest of the process, holding the rows open. Chunks are now read in the caller's own goroutine, and the rows are closed the moment the loop ends, however it ends. The query runs when the loop starts, so a failure to build or run it arrives as the first value of the loop rather than as a second return value.
- Errors that carry another error as their cause now wrap it with `%w` instead of formatting it into text, so `errors.Is` and `errors.As` reach the cause — for example a CSV whose encoding cannot be detected, a CCL sequence or aggregate function that fails, and the `csvxl`, `pd` and `datafetch` paths that reported a wrapped failure as a string. The message text is unchanged.
- Reading and writing no longer require a file on disk. `ReadCSV(r io.Reader, opts)` reads CSV from any source — an HTTP response body, a zip entry, an `embed.FS` file, bytes in memory — and detects its encoding from its first bytes when `Encoding` is empty; `ReadCSV_FileWithOptions` and `ReadCSV_StringWithOptions` now call it, so the same bytes give the same table either way. `StreamCSV(r, opts, batchSize)` reads a CSV a batch at a time, holding only the current batch, as `for dt, err := range insyra.StreamCSV(...)`; the header names every batch's columns and types are inferred per batch. `ReadJSON` accepts an `io.Reader`, `ReadExcel(r, sheet, …)` reads a workbook from a reader with the same unzip limit as `ReadExcelSheet`, and `(*DataTable).WriteCSV` and `WriteJSON` write to any `io.Writer`, which `ToCSVWithOptions` and `ToJSON` now use. Nothing existing changed signature.
- A DataTable can now be written to Excel. `(*DataTable).ToExcel(path, ExcelWriteOptions)` writes the table as one sheet of a workbook and leaves the workbook's other sheets as they were, creating the file if needed, so a report can keep one sheet per year. If the sheet already exists the call returns an error matching `ErrSheetExists` and does not touch the file; with `IfSheetExists: SheetExistsReplace` it replaces that sheet in its original position, hidden again if it was hidden, and leaves the names other sheets define with them. `Sheet` defaults to `Sheet1`. Numbers, booleans and times are stored as Excel values. `(*DataTable).WriteExcel(w, opts)` writes a one-sheet workbook to any `io.Writer`.
- **BREAKING**: `ToFloat64`, `ToFloat64Safe` and `ReadSlice2D` are now functions instead of variables holding a function. Calling them is unchanged. Only assigning to one no longer compiles: `insyra.ToFloat64Safe = …` used to replace the conversion that `stats`, `ml`, `nn`, `quant` and the core all call, changing every result in the process. `ReadSlice2D` is now the one name for turning a 2D slice into a DataTable; `Slice2DToDataTable` still works, is **Deprecated**, and will be removed in the next release.
- The scalers, `SimpleImputer` and the one-hot, label and ordinal encoders explain a column they cannot find the way every other column selector does. `NewStandardScaler().FitTransform(dt, "Age")` on a table with a column named `Age` used to fail with `column Age not found`, which reads as though the column were missing; it now says that `"Age"` reads as an Excel-style column index and to write `Name("Age")`.
- **BREAKING (behaviour, not signature)**: a trailing optional parameter takes at most one value. `DataList.Shift` and `DataTable.ShiftCol` with two fill values, `FillForward`/`FillBackward` with two limits, `FillByInterpolation` with two flags, `Sample`/`SampleFrac`/`Shuffle`/`TrainTestSplit` with two `SamplingOptions` and `Describe` with two `DescribeOptions` used to keep the first value and drop the rest without a word; they now record an error and change nothing. `Rank(true, false)` used to record an error and rank anyway; it no longer ranks. `ReadSQL`, `ReadSQLContext`, `ReadSQLStream`, `ToSQL`, `ToSQLContext` and `ReadCSV_File` return an error for a second options struct or encoding.
- `DataList.DataType()` and `DataTable.ColDataTypes()` tell a program what kind of values a column holds: `DataTypeNumber`, `DataTypeString`, `DataTypeBool`, `DataTypeTime`, `DataTypeOther`, `DataTypeMixed`, or `DataTypeEmpty` when there are none. Missing values are left out, integers and floats are both numbers, and text that looks numeric stays text. `ShowTypes` could only print each cell's Go type for a person to read; it now opens with a `DataType` row that shows the same verdict above the per-cell types.
- **BREAKING**: `DataTable.FillByInterpolation` takes `extrapolate bool` before its columns, as `FillForward` takes its limit, because the table version could not extrapolate at all. `dt.FillByInterpolation(cols...)` becomes `dt.FillByInterpolation(false, cols...)`.
- `FillWithMean`, `FillWithMedian`, `FillByInterpolation` and `FillWithMode` on a table record an error for a column you named and they cannot fill (text or mixed for the numeric fills, or no values at all), naming the column and its data type; the other named columns are still filled. They used to skip it without a word, so the caller believed it filled. With no columns named, a column they cannot fill is still skipped.
- **BREAKING**: `NewSimpleImputer` takes an optional `SimpleImputerOptions{Strategy, FillValue}` instead of `(strategy, constant ...any)`. With no options it fills with the mean. `NewSimpleImputer(insyra.ImputeMedian)` becomes `NewSimpleImputer(insyra.SimpleImputerOptions{Strategy: insyra.ImputeMedian})`, and `NewSimpleImputer(insyra.ImputeConstant, 7)` becomes `…{Strategy: insyra.ImputeConstant, FillValue: 7}`.
- **BREAKING (behaviour, not signature)**: `SimpleImputer.Fit` with the mean or median fails when a selected column is not a number column, naming it and its data type, and learns nothing. It used to leave such a column unfilled and report that only through `Params()[name].PassThrough`, so a fit looked complete when it was not. `ScalerParams.PassThrough` is now always false and **Deprecated**; it will be removed in the next release.
- `ShowRange`, `ShowTypesRange` and `Show`'s range print an error line for more than two values, a first value that is not an `int`, or an end that is neither an `int` nor `nil`; they used to ignore such arguments and show everything. `ShowHead(n)` and `ShowTail(n)` (with `ShowHeadTo`/`ShowTailTo`) on both DataList and DataTable are plainer spellings of `ShowRange(n)` and `ShowRange(-n)`.
- **BREAKING**: the CSV and JSON readers and writers have one name each and take their settings in one optional options struct. `ReadCSVFile(path, opts...)` and `ReadCSVString(s, opts...)` replace `ReadCSV_File`/`ReadCSV_FileWithOptions` and `ReadCSV_String`/`ReadCSV_StringWithOptions`; `ReadJSONFile` replaces `ReadJSON_File`; `ToJSONBytes`/`ToJSONString` replace `ToJSON_Bytes`/`ToJSON_String`. The old names still work in this release, keep their old meaning, and are **Deprecated**; they are removed in the next.
- **BREAKING**: `DataTable.ToCSV(path, opts ...CSVWriteOptions)` replaces `ToCSV(path, rowNames, colNames, bom bool)`, which no longer compiles; `ToCSVWithOptions` is **Deprecated**. `dt.ToCSV(path, false, true, false)` becomes `dt.ToCSV(path)`. `WriteCSV` and `ReadCSV` take their options as optional, and `StreamCSV` takes the batch size before them: `StreamCSV(r, opts, 1000)` becomes `StreamCSV(r, 1000, opts)`.
- **BREAKING**: a file's header row and row names are spelled `NoHeaderRow` and `HasRowNames` in every options struct, so the zero value is the common file: the first row names the columns and no column holds row names. `CSVReadOptions.FirstRowToColNames` and `CSVWriteOptions.SetColNamesToFirstRow` become `NoHeaderRow` with the opposite meaning; `FirstColToRowNames` and `SetRowNamesToFirstCol` become `HasRowNames`; `ExcelWriteOptions` follows, and `ToSQLOptions.RowNames` becomes `HasRowNames`. Code that set the old fields stops compiling. **Code that passed an options struct without the header field now reads and writes a header row**: `CSVReadOptions{Encoding: "big5"}` used to take the first row as data. `ReadExcelSheet` and `ReadExcel` only renamed their parameters.
- **BREAKING (small)**: `IDataTable` and `IDataList` list every method of `*DataTable` and `*DataList`; 27 and 17 were missing. The exceptions are `ClearErr`, `SetErr`, `Pivot` and `Unpivot`, now left out on purpose because an extension that embeds the core type overrides them with its own return type; code that called `ClearErr()` or `SetErr()` on a variable typed as the interface must use the concrete type. A type that embeds `*DataTable` now goes everywhere a table goes: `Merge` used to reject anything but a bare `*DataTable`.
- `Err()` on a nil `DataList` or `DataTable`, such as the one `GetCol` returns for a missing column, reports `nil DataList`/`nil DataTable` instead of crashing. Only `Err()` is guarded: every other method on a nil value still fails loudly, so the nil cannot travel on unnoticed.
- **BREAKING**: `Counter()` keys every integer by its value, as an `int`, so it agrees with `Count`. A CSV or JSON load stores integers as `int64`, so `counter[5]` used to find nothing on a column holding two fives, and a column mixing `int64(5)` with a Go literal `5` reported two keys while `Count(5)` reported their total. Now `counter[5]` is 2 in both cases. Code that indexed a counter with `int64(5)` finds nothing and must write `counter[5]` or `counter[insyra.ToMapKey(v)]`, and code that type-asserts a key as `int64` must assert `int`. `ToMapKey` turns an integer of any width into the same key. An integer an `int` cannot hold keeps `uint64` or `int64`, and floats and text stay keys of their own, as in `Count`.
- `StandardScaler`, `MinMaxScaler`, `RobustScaler` and `MaxAbsScaler` implement `json.Marshaler` and `json.Unmarshaler`, so a fitted scaler can be saved and used again later. Read back with `json.Unmarshal` into the same type, it transforms tables exactly as the original does: each fitted column is remembered by its name, or by its position when it has no name, and NaN parameters come back as NaN. `json.Marshal` of a scaler used to produce `{}`.
- CCL's `TOSTR` refuses a format whose verb is a punctuation mark or a non-ASCII letter and has no value left, as it already did for a letter: `TOSTR(A, '%v %_')` wrote `1 %!_(MISSING)` into the cell in v0.3.3.
- A nested array and a nested slice holding the same elements are one value to `Count`, `Counter`, grouping and merging at any size. v0.3.3 wrote a large nested slice as a digest and an array never, so the two stopped matching once their contents passed about 1 KiB.
- **BREAKING**: `ProcessData` returns `([]any, error)` instead of `([]any, int)`. The int was only the slice's length, and a value it could not read came back as `nil, 0` with a log line, which a caller could not tell from an empty slice. A type it cannot read, a `nil` input and a nil pointer are now an error, and a nil `*DataList` no longer crashes it. Write `values, err := insyra.ProcessData(x)` and take the length from `len(values)`.
- `SqrtRat`, `PowRat`, `SortTimes` and `F64orRat` are **Deprecated** and are removed in the next release. Nothing in insyra uses them, and each doc comment names the `math/big` or `slices` code that replaces it. Two are fixed for the release they have left: `SqrtRat` of a negative number or `nil` returns `nil` instead of panicking, and `PowRat` with a negative exponent returns the reciprocal, where `PowRat(big.NewRat(2, 3), -2)` returned `1`. `PowRat(nil, n)` and zero to a negative power return `nil`.
- Added `DataTable.FilterRowsWhere(keep func(row *DataList) bool)`. It keeps the rows for which `keep` returns true and hands `keep` the whole row, so a condition can compare two columns: `dt.FilterRowsWhere(func(row *insyra.DataList) bool { return insyra.ToFloat64(row.Get(0)) < insyra.ToFloat64(row.Get(1)) })`. `Filter` and `FilterRows` call their function once per cell and keep a row when any cell passes, which their documentation now says plainly. `Filter`'s column argument is the Excel-style letter; the documented example that compared it with a column name never matched and is corrected. `FilterByCustomElement` returns exactly what `Filter` returns, is **Deprecated** in its favour, and is removed in the next release. `Filter` and `FilterRows` no longer crash with an index out of range when their function adds a column to the table being filtered.
- Added `DataTable.SliceRows(from, to)` and `SliceCols(from, to)`, which take a contiguous range of rows or columns the way `s[from:to]` slices a Go slice: `from` included, `to` excluded. `SliceRows` takes 0-based positions. `SliceCols` takes each bound as a column selector, so `SliceCols("B", "D")`, `SliceCols(1, 3)` and `SliceCols(insyra.Name("b"), insyra.Name("d"))` are the same call on a table whose columns are named that way, and `nil` runs from the first column or to the last. A bound the method cannot use records an error and returns an empty table instead of panicking. The ten methods that did this under filter names, `FilterColsByColIndex…` and `FilterRowsByRowIndex…` with `GreaterThan`, `GreaterThanOrEqualTo`, `EqualTo`, `LessThan` and `LessThanOrEqualTo`, are **Deprecated** and removed in the next release; each doc comment names the slice it stands for. They keep their results, except that `FilterColsByColIndexLessThan` and `…LessThanOrEqualTo` given a letter past the last column now keep every column, where they panicked. `Headers` and `SetHeaders` are **Deprecated** in favour of `ColNames` and `SetColNames`.
- **BREAKING**: `PivotConfig.AggFunc` takes the `AggregateOp` that `Aggregate` and `Resample` take, as a pointer: `AggFunc: new(insyra.OpSum)` instead of `AggFunc: "sum"`. `nil` still means no aggregation, so duplicate `(Index, Columns)` rows are an error; a plain `AggregateOp` field could not say that, because `OpSum` is its zero value. The string aliases (`"avg"`, `"std"`, `"average"` and the rest) go with the string, and a misspelled op no longer compiles.
- `GroupBy`, `Pivot`, `Merge` keys, `OpNUnique` and `Describe`'s unique count put a `uintptr` with the other integer widths, as `Count` and `Counter` already did; it used to form a group of its own. The rule is now written at `GroupBy` in `Docs/DataTable.md`: integers group by value whatever their width, so a CSV load's `int64(1)` and a Go literal `1` share a group, while `1`, `1.0` and `"1"` stay three groups.
- `ShowRange`, `Show` and `ShowTypesRange` on a DataTable size their columns from the rows they print instead of formatting every cell of the table. `ShowRange(5)` on a 1,000,000 × 3 table took 279–437 ms and now takes about 40 µs; `ShowTypesRange(5)` went from about 175 ms to 18 ms, and `Show()` from about 500 ms to 300 ms, the rest being its stat line, which covers every row. A view that prints every row is unchanged; a view of part of a table can be narrower, because a wide cell outside it no longer widens its columns. `Show`'s parameter type is exported as `Showable`, so a function of your own can take anything `Show` takes.
- `ToSQL` with `IfExists: SQLActionIfTableExistsReplace` no longer loses the old table on MySQL when the write fails. MySQL commits a `DROP TABLE` the moment it runs, even inside a transaction, so an `INSERT` that failed after it, for example one past the 65,535-placeholder limit, left neither the old table nor the new rows. On MySQL, Replace now writes the rows into a staging table (`insyra_new_<random>`) and puts it in place with one `RENAME TABLE`, then drops the old table; a failed or cancelled write drops the staging table and leaves the old one as it was. Because the staging table has a name of its own, Replace on MySQL now needs the CREATE, INSERT, ALTER and DROP privileges on the database, not only on the table, and it refuses a table that another table references by foreign key; both fail before anything changes. SQLite and PostgreSQL, whose DDL is transactional, still drop and recreate inside one transaction. The `ToSQL` documentation no longer says every statement is rolled back on every database: on MySQL a table created because it did not exist, and columns added in append mode, stay behind after a failed write.
- **BREAKING**: `DataList.WeightedMean` and `WeightedMovingAverage` take their weights as a `[]float64`, the type `RollingOptions.Weights` already uses. They took `any` and worked out at run time whether it was a slice, an array or a `DataList`, and anything else became an empty set of weights that failed the length check with a message about the length. A call that passes a `[]float64` compiles unchanged; one that passes a `DataList`, a `[]int` or a `[]any` stops compiling and has to convert its weights first. The results are unchanged.
- **BREAKING**: `DataList.ParseNumbers` types the list the way the CSV reader types a column. When every number in it is an integer and no string is empty, every number becomes `int64`; otherwise every number becomes `float64` and an empty string becomes `NaN`. It turned everything into `float64`, so `"9007199254740993"` came back as `9007199254740992` and `NewDataList("1", 2).ParseNumbers()` gave `[1.0 2.0]` where it now gives `int64` values. Numbers already in the list take part and are converted to the same type. `nil` is left alone and is no longer reported as a failure; text that is not a number, and values such as a `bool`, are left as they were and reported by one error that counts them and names the first row, where each used to be reported separately.
- A window transform that cannot run says why on the list it returns. `Rolling` with a `Window` below 1, a `MinObs` above `Window` or `Weights` of the wrong length, `EWM` without exactly one decay parameter, `Apply(nil)`, and `Corr`, `Cov` and `Beta` with a `nil` list returned an empty list whose `Err()` was `nil`; it now carries the error. `DataTable.RollingCol` and `EWMCol` computed on a copy of the column, so an invalid option was recorded on nothing the caller held: it is now recorded on the table too. `ShiftCol`, `DiffCol`, `PctChangeCol`, the four `Cum*Col` and the three window builders return an empty list carrying the table's error for a column that is not there. A grouped transform with an invalid argument (`RollingCol` with `Window: 0`, `DiffCol` with `periods` 0, `ShiftCol` with two fill values) returned a full-length column of `nil` and recorded nothing; `.As` now records the error on the table and returns an empty list carrying it. The result stays empty rather than becoming a list of `nil`, which a valid window with too few observations also returns.
- **BREAKING (display only)**: `Show`, and `ShowRange` and `ShowTypesRange` called with no range, print a table or a list of up to 60 rows whole, where they used to cut at 25; past 60 they still print the first 20 and last 5 rows with `...` between. pandas prints up to 60 rows whole as well, though it shows 5 and 5 past that. Code that parses the printed output of a 26 to 60 row view sees every row now. The documentation said `ShowRange()` showed every row, which was never the case past 25; it now states the rule.
- `DataList.Difference`, `MovingAverage`, `MovingStdev` and `WeightedMovingAverage` are **Deprecated** and are removed in the next release. They keep their behaviour until then. Their replacements are `Diff(1)`, `Rolling(RollingOptions{Window: w}).Mean()`, `Rolling(...).Std()` and `Rolling(RollingOptions{Window: w, Weights: ws}).Mean()`, which are not drop-in: they keep the input's length with leading `nil` (`MovingAverage(3)` on five values gives three, `Rolling` gives five), and they give `nil` for a gap where the older methods fail or return `NaN`. On a fully numeric list, `Data()[w-1:]` of the replacement is the older result. `Docs/DataList.md` lists every difference under "Methods that look alike but differ". `ExponentialSmoothing` is not deprecated, because `EWM` refuses `alpha = 0`.

- **BREAKING**: an environment name may contain only letters, digits, `.`, `_` and `-`, must start with a letter or digit, and may not contain `..`. v0.3.3 refused only a name that resolved outside the environments directory and accepted any other, including names with spaces, non-ASCII letters or a `/`. The CLI can no longer open, rename or delete an environment created under such a name; rename its folder in the environments directory (`~/.insyra/envs/` by default) by hand.
- **BREAKING**: a command that could not do what it was asked now returns an error and exits non-zero instead of printing its success line. `sort`, `dropcol`, `droprow`, `swap`, `setcolnames` and `sample` check their target first and name what was missing; `ccl` and `addcolccl` report an expression that would not compile. A script whose step has been silently ignored will now fail.
- **BREAKING**: a misspelled option value is rejected instead of falling back to the default. `sort … dsc`, `ttest … eqaul`, `ztest … bogus` and `clean … outliers abc` used to run with ascending order, pooled variance, a two-sided alternative and 2.0 standard deviations respectively — a statistical result computed under an assumption the caller never made.
- **BREAKING**: `plot`, `fetch` and `merge` report an argument they do not understand instead of dropping it, and `plot`'s usage no longer advertises options it never accepted.
- `config` refuses an unknown key (listing the ones it takes) and validates `log-level`, `no-color` and `accel-mode`, so nothing invalid reaches the config file.
- `sample` rejects a size of zero or below, or one larger than the source without replacement, instead of saving an empty result; `setcolnames` requires exactly one name per column instead of blanking the rest or adding empty columns.
- `encode … ordinal … order` matches the integers in CSV-loaded tables, and in every variable restored between one-shot commands. It compared the typed `1`, an `int`, with stored `int64` values, so `encode … order 1,2,3` encoded every cell as nil.
- **BREAKING**: `accel` and the nine DataList statistics (`sum`, `mean`, `median`, `mode`, `stdev`, `var`, `min`, `max`, `range`) reject an argument they do not use instead of ignoring it. `mean x as m` printed the mean and stored nothing; it is now an error that names the argument. `accel` no longer accepts `--precision`, which chose the precision of the `accel run` removed in v0.3.1 and has been read by nothing since.
- Fixed `insyra env import` overwriting a non-empty environment without `--force` when one of its files existed but could not be read. The check that decides whether the target is empty took a failure to read `config.json` as "empty", and ignored failures to read `state.json` and `history.txt` the same way. A missing file still counts as empty; any other failure now stops the import and says which environment could not be checked.
- `save` writes Excel: `save <var> report.xlsx [sheet <name>] [if-exists fail|replace]`. It writes one sheet (default `Sheet1`) and keeps the workbook's other sheets. Saving to a sheet that already exists is refused rather than renamed to `Sheet2`, and the message says to add `if-exists replace` to overwrite it or, when no sheet was named, `sheet <name>` to save a new one. `.xls` is refused with a pointer to `.xlsx`, and `sheet` and `if-exists` are refused for other file types. `save … report.xlsx` used to fail with `unsupported output file type`.
- `fillna` on a table honours `extrapolate`, which was dropped. A fill that could not do what it was asked now fails and saves nothing: a column named in `cols` that the fill cannot handle, or `mean` on a text list, used to be saved as though filled.
- `convert` from xlsx to csv guards formula-like text by default and takes `allowformulas true` to write it exactly, like `save`. An argument `convert` does not understand is now an error instead of being ignored.
- **BREAKING**: every command refuses an argument it does not take. More than fifty commands, among them `iqr`, `cov`, `corr`, `summary`, `get`, `find`, `transpose`, `ttest` and `version`, used to read the arguments they needed and drop the rest, so `iqr x junk` printed an answer as if the call were right and `find t 1 as found` stored nothing. The command now does not run, and the error names the argument and shows the usage: `iqr: unexpected argument "junk"; usage: iqr <var>`. `as <var>` is accepted only by commands that store a result. In a `.isr` script the line fails and `run` goes on to the next one.
- **BREAKING**: every token that picks a column or a row follows one rule. `col`, `sort`, `swap` and `dropcol` found `price` but not `B`, `get` and `set` found `B` but printed `<nil>` for `price`, and `fillna` and `groupby` took both, name first. A bare token is now read every way it can be: digits as a 0-based number, negative counting from the end; letters as an Excel-style index, for columns; and as a name. When the readings agree the command uses that column, so `sort t price`, `sort t B` and `sort t 1` all work and `2021` still finds a column named for the year. When two readings point at different columns the command stops and says which to write instead of guessing: on a table with columns `x, a`, `sort t a` answers that `a` could be index A (`x`) or the column named `a`, and to write `index:a` or `name:a`. `number:`, `index:` and `name:` pick one reading; rows take `number:` and `name:`, and `get` and `set` now accept a row name. The rule covers `col`, `row`, `get`, `set`, `sort`, `swap`, `dropcol`, `droprow` and the column lists of `fillna`, `groupby`, `describe`, `encode`, `parsedates`, `pivot`, `unpivot`, `resample`, `scale` and `merge … on`.
- A command that fails no longer makes the next one fail. The table kept the library's record of the failure, so after `col t B` failed, a `sort t price` that had just worked reported "no column is named B".
- One-shot commands no longer change the variables they restore. `state.json` now stores each variable with its Go types: a DataTable keeps its column order, its column and row names, and the type of every cell, so after `insyra load c.csv as t` a separate `insyra cols t` lists the columns in the file's order instead of alphabetically, column letters point at the same column in every command, a column `parsedates` turned into dates is still dates for `resample`, a date difference computed by CCL stays a `time.Duration`, and a `3.0` stays a `float64` instead of coming back as an `int64`. A fitted scaler from `scale fit` and a tree from `hclust` are saved too, so `scale transform` and `cutree` work as separate commands. Before, the scaler was gone and `cutree` refused the tree.
- A variable the environment cannot store, such as a `regression` result, is reported with a `warning:` line when the environment is saved, once per variable in the REPL or a script, instead of being dropped or turned into a map without a word. The command that created it still succeeds, and every other variable is saved. Go code that drives `cli/env` directly can get the same list from the new `Manager.SaveVariables`, and `SaveState` still returns an error only when the file was not written.
- `state.json` files written by earlier releases still load and are rewritten in the new layout the next time the environment is saved. `env export` of an environment holding a NaN value no longer fails, and `env import` keeps integers above 2^53 exact.
- `pivot … agg <op>` reads the op the way `groupby` and `resample` do, as the documentation already said. `agg average`, which only `pivot` accepted and never documented, is now refused, and so is `agg custom`, which failed anyway because the CLI cannot pass a function.
- `rolling` reports a window the library refuses as an error and stores nothing: `rolling x 0 mean` and `rolling x 2 mean minobs 3` printed `saved as $result` and stored an empty list. `ewm` reports the library's error instead of inferring failure from the result's length.
- `parsenums` follows `ParseNumbers`: a list whose numbers are all integers parses to `int64` instead of `float64`.
- **BREAKING**: `ttest two <var1> <var2>` without `equal` or `unequal` runs Welch's t-test, the library's default, instead of assuming equal variances. Add `equal` to keep the old result; `help ttest` states the default.
- `fillna … ffill|bfill … missing nan|nil` no longer counts the other kind of missing value toward `limit`. The command filled both kinds and then put the other kind back, so the other kind's cells used up the limit: `fillna x ffill limit 1 missing nan` on `[1, nil, NaN]` left the `NaN` unfilled. Those cells are now skipped, so the result is `[1, nil, 1]`. Without a `limit`, and for `mean`, `median`, `mode` and `interpolate`, results are unchanged.
- `plot` reports why a chart could not be built, for example `plot: CreateLineChart: no data to draw` for a table with no columns, instead of `failed to create chart`.

### `ml` and `nn`
- **BREAKING (behaviour, not signature)**: `Classes()` never returns nil. On the ten classifier types across `ml` and `nn`, a model that has no classes to report — it was not fitted, or a pipeline wraps something that is not a classifier — now returns an empty `*insyra.DataList` whose `Err()` says which, instead of nil. A nil `*insyra.DataList` used to panic on every method, `Err()` included, so the caller's first safe move — asking the value what went wrong — was itself the crash. **The signature is unchanged, so nothing stops compiling: code written as `if classes == nil` keeps building and its branch never runs again.** Replace it with `if classes.Err() != nil`.
- **BREAKING (behaviour, not signature)**: `nn.NewTape` takes at most one seed; a tape given two reports the error from `Param` and `Backward` instead of using the first. `Conv2D`, `MaxPool2D`, `AvgPool2D` and their `New…` spellings given more than one options struct used to discard all of them and build with the defaults; the layer now reports the error from `Build`.
- **BREAKING**: `Tape.BatchNormalizationTraining` and `BatchNormTraining` take `opts ...nn.BatchNormOptions{Momentum, Epsilon}` instead of `options ...float32` read by position, so epsilon can be set without restating momentum and a reader can tell the two apart. A zero field keeps torch's default. `…, 0.2, 1e-5)` becomes `…, nn.BatchNormOptions{Momentum: 0.2, Epsilon: 1e-5})`.
- Added `Tape.Custom(name, inputs, output, vjp)`, which puts an operation computed outside the tape on it: its inputs receive the gradients its reverse rule returns, where before a tensor computed outside the tape silently gave its inputs a zero gradient. The rule may differ from the forward derivative, such as a surrogate for a hard threshold. `Custom` refuses a malformed declaration, including an output an operation recorded earlier has already read, and a rule that returns an error or a gradient of the wrong count, type or shape fails `Backward` naming the operation. ([issue #375](https://github.com/HazelnutParadise/insyra/issues/375))
- Added `Tape.BackwardFrom(output, upstream)`, which starts the reverse pass from any tensor an operation on the tape produced, seeded with an explicit upstream gradient of its shape. ([issue #375](https://github.com/HazelnutParadise/insyra/issues/375))
- A `Backward` that fails no longer leaves `Tape.Grad` returning a half-built gradient: both `Tape.Grad` and `Parameter.Grad` keep what the last successful pass computed.
- Added `NewEdgeTopology`, `EdgeSum` and `Tape.EdgeSum` for graphs given as edge lists: each node sums its weighted incoming edges in O(E + size of the values), with no dense N×N matrix, and the tape gives gradients for the edge weights and the node values. Values may be `[N]` or batched `[B, N]`. Each output is the exact sum of its products rounded once to the nearest float32, so the order of the edges and the number of cores cannot change it on any platform; a large graph uses every core. ([issue #379](https://github.com/HazelnutParadise/insyra/issues/379))
- `Tanh` returns the correctly rounded value, the true `tanh(x)` rounded once to the nearest float32, for every input on every platform. It used to round Go's `math.Tanh`, whose float64 result is not the same on every platform (it fuses multiply-adds on arm64, picks an FMA path at run time on amd64, and is assembly on s390x), so it was correct only where that result happened to be accurate enough. All 2^32 inputs were checked on darwin/arm64, and the inputs between 2^-13 and 9.5 on linux/amd64 and windows/amd64. The old results were already correct on all three, so nothing changes there.
- `Tape.Tanh`'s gradient rounds every step to float32. Go's compiler used to fuse `1 - y*y` into one multiply-add on arm64 but not on amd64, so the same gradient could differ in its last bit between the two; on arm64, 24,892 of 100,000 random gradients change. It is now the same bits on every platform.

### `stats`
- **BREAKING**: `FactorAnalysis` with `Rotation.Method: FactorRotationOblimin` and `Rotation.Restarts` above 1 now runs the search the parameter describes. Oblimin built its own identity start on every pass and ignored the one it was handed, so `Restarts: 20` performed the same computation twenty times and returned the first result — measured, twenty starts took 202 ms to return the 9.9 ms answer. It now rotates from each start exactly as the other nine methods do, and at `Delta: 0` its result is bit-identical to Quartimin's for the same `Restarts`, because the two are the same criterion. On the twelve generated datasets in the test suite the loadings move by at most 1.2e-5; on an over-factored model — four factors fitted to three-factor data — the extra starts reach a basin the identity start never does, with a criterion value 47 times lower. That solution also has a factor correlation of 0.905: the lowest criterion value is what `Restarts` asks for, not a promise that the solution is the one you want, and that is true of every oblique rotation with more than one start. `Restarts: 1`, the default, is unchanged. SPSS's Direct Oblimin is single-start, and `Restarts: 1` still is.
- **BREAKING**: `DefaultFactorAnalysisOptions()` sets `Rotation.Restarts` to 20, and a `Restarts` left at zero means 20. This follows psych 2.6.5, which changed `fa()`'s `n.rotations` default from 1 to 20 after a real example of a single start stopping in a local minimum; `fungible::faMain` defaults to 10 for the same reason. The rule among starts is unchanged and is now a recorded decision: the lowest criterion value among the starts that converged, as `GPArotation`'s engine and `fungible` do — psych ranks by hyperplane count, and on every dataset measured the two rules chose the same solution. On the twenty datasets in the test suite the default loadings move by at most 1.2e-5 and never to a different solution. The informed Varimax start built for a multi-start search now runs at the rotation's own tolerance (`eps = 1e-5`, `maxit = 1000`) instead of `1e-8` / `5000`, where it hit the iteration cap and cost 80 ms on five of those datasets; the whole twenty-start search costs 1.5 to 9 ms on them. Set `Restarts: 1` for the single identity start SPSS and `GPArotation` use by default.
- **BREAKING**: Promax with MINRES, ML or PAF extraction now follows psych 2.6.5. psych's `fa()` reaches Promax through `kaiser()` and `psych::Promax`, whose pre-rotation became `GPArotation::Varimax` in 2.6.5 ("replaced with GPArotation Varimax 5/9/26"); `principal()` still uses `stats::promax`, whose pre-rotation is `stats::varimax` with Kaiser normalisation. Ours pre-rotated every Promax the `stats::varimax` way, so with a factor extraction it gave the pre-2.6.5 answer. On data with a clear varimax optimum the two pre-rotations agree to the convergence tolerance, but on the parity suite's ten-row table the varimax criterion is nearly flat, they stop at different angles, and Promax raises the difference to the fourth power — loading[0,0] was 0.700 against psych's 0.625. Measured against psych 2.6.5 over 16 datasets: MINRES, ML and PAF now agree to 6.4e-4 at worst, where it was 0.29. Results with PCA extraction are unchanged and agree to 4e-13.
- **BREAKING**: every gradient projection rotation in `FactorAnalysis` now steps the way GPArotation 2026.8.2 does by default, and runs up to 2000 iterations from each start instead of 1000. That covers Varimax, Quartimax, GeominT, BentlerT, Quartimin, Oblimin, GeominQ, BentlerQ and Simplimax, and the Varimax step of Promax after a factor extraction. The rotation had been ported from GPArotation's older step, which GPArotation has since replaced with its `"bb"` algorithm as the default, and psych 2.6.5 uses that default. The older step makes slow progress along a nearly flat criterion: on two ten-row tables fitted with two factors, quartimin converged within 1000 iterations from 7 and 31 of 400 random starts, and geomin from 0 and 3, while GPArotation converges from all 400 in under 200 iterations. Rotations that stopped at the old cap now converge, so their loadings can move and `RotationConverged` can change to `true`. A multi-start search can choose a different solution, because more of its starts finish. The `stats::varimax` step used by Promax after principal components is unchanged. On the ten-row table where Promax with MINRES differed from psych 2.6.5 by up to 5e-4, it now agrees to 1e-10.
- **BREAKING**: `FactorAnalysis` with `FactorRotationSimplimax` now minimises the simplimax criterion psych 2.6.5 minimises. psych calls `GPArotation::simplimax` without a `k`, and that criterion adds up exactly the `k` smallest squared loadings, with `k` = the number of variables × (the number of factors − 1), taking equal squared loadings by column-major position. The rotation here used `k` = the number of variables and also added every squared loading equal to the `k`-th smallest. With three or more factors, or with equal squared loadings, it therefore minimised a different criterion and returned a different rotation: on a 6-variable, 3-factor loading matrix the criterion at the start was 0.125 where GPArotation's is 0.245, and the rotation drove it to 3e-9 where GPArotation stops at 0.0218. With two factors and no equal squared loadings nothing changes.
- `PairedTTest`, `SingleSampleWilcoxon`, `PairedWilcoxon`, `MannWhitneyU`, `OneWayANOVA`, `TwoWayANOVA`, `RepeatedMeasuresANOVA`, `KruskalWallis` and `FriedmanTest` refuse a `NaN` or `±Inf` cell, which is what the `stats` documentation has always said of every numeric entry point. They checked only that a cell converts to a number, so the value went into the arithmetic and came back with a nil error: `PairedTTest` and the three ANOVAs returned a `NaN` statistic and p-value, and the rank tests returned an ordinary-looking answer, because a `NaN` still gets a rank. `KruskalWallis` on `[1, 2, NaN, 4]` against `[1, 2, 3, 4]` reported H = 0.54, p = 0.46. Their errors now read like the other tests' and count both the list and the position from one, as in `group 2 contains a non-finite value at row 3: NaN`, `cell (A=2, B=1) contains a non-numeric value at row 2: <nil>` and `subject 2 contains a non-finite value at condition 2: NaN`, with `data1` or `data2` naming the list in the paired and two-sample tests. They used to say `invalid numeric value in data1`, with no position, or `invalid data at group 0 index 2`, counted from zero. `LeveneTest` and `BartlettTest` now number groups from one as well (their `group 1` used to mean the second group), and so do the errors for an empty group, an empty cell and a subject with the wrong number of conditions. A `nil` list, typed or not, gets the error an empty list gets. `OneWayANOVA`, `KruskalWallis` and `FriedmanTest` used to end the program on one, from inside a goroutine no `recover` could reach, and `TwoWayANOVA`, `RepeatedMeasuresANOVA` and `SingleSampleWilcoxon` panicked. Results on fully finite input are unchanged. The CLI's `ttest paired`, `anova` and `ftest levene|bartlett` commands print the new messages.
- A list that is not a `*insyra.DataList` itself, such as one from `isr.DL`, is read as it is stored. `stats` used to rebuild such a list with `NewDataList`, which splits a slice cell into several numbers, so `SingleSampleTTest` and the other functions that convert their input counted a slice cell as extra observations, and a four-cell list reached `PairedTTest`'s length check as five cells. The cell is now refused, as the same cell in a `*insyra.DataList` already was: `data contains a non-numeric value at row 4: [10 11]`.
- `CutTreeByK` and `CutTreeByHeight` refuse a tree whose merges, heights and labels do not fit together, or whose merge joins something that is neither a leaf nor an earlier merge, with an error naming the problem. A tree with fewer heights than merges panicked; one built by hand or restored from a file can be any shape, and the CLI now restores `hclust` trees between one-shot commands.
- `Skewness` and `Kurtosis` report input they cannot read, a nil `*DataList` included, as an error starting `sample:`. A nil list crashed them, and a value of another type, such as a plain number, was reported as `empty data`.
- **BREAKING**: the hypothesis tests take their alternative hypothesis and confidence level one way, in an optional options value passed last. The t-tests take `opts ...TTestOptions` instead of `confidenceLevel ...float64`; the z-tests take `opts ...ZTestOptions` instead of a required `alternative` and `confidenceLevel`; `SingleSampleWilcoxon` and `PairedWilcoxon` take `opts ...WilcoxonOptions` and `MannWhitneyU` takes `opts ...MannWhitneyUOptions`, instead of a required `alt` and an optional `confidenceLevel`. Each struct has `Alternative` and `ConfidenceLevel`, and leaving it out, or a field at zero, means a two-sided test with a 95% interval, so `SingleSampleZTest(x, 100, 15)` and `MannWhitneyU(a, b)` now work as they read. Rewrite `SingleSampleTTest(x, 50, 0.99)` as `SingleSampleTTest(x, 50, stats.TTestOptions{ConfidenceLevel: 0.99})`, and `SingleSampleZTest(x, 100, 15, stats.Greater, 0.95)` as `SingleSampleZTest(x, 100, 15, stats.ZTestOptions{Alternative: stats.Greater})`. A level outside (0, 1) other than 0 is still an error, and so is `NaN`, which used to get through: the t- and Wilcoxon tests reported a 95% interval for it and the z-tests an interval of `[NaN, NaN]`, with a nil error. An unknown alternative, and a second options value, are errors as well. Every result the old calls could produce is unchanged.
- The t-tests can be one-sided. `TTestOptions{Alternative: stats.Greater}` or `stats.Less` gives the p-value and the one-sided interval R's `t.test(..., alternative = "greater")` reports, with the open end at `+Inf` or `-Inf`, as the z-tests already report it. All three t-tests are checked against R's `t.test` and SciPy for both directions at two confidence levels.
- **BREAKING**: `OneWayANOVA`, `TwoWayANOVA`, `RepeatedMeasuresANOVA`, `KruskalWallis` and `FriedmanTest` take their groups, cells or subjects as one `[]insyra.IDataList`, as `LeveneTest` and `BartlettTest` already did. `OneWayANOVA(a, b, c)` becomes `OneWayANOVA([]insyra.IDataList{a, b, c})`, and `OneWayANOVA(groups...)` becomes `OneWayANOVA(groups)`. Go allows only the last parameter to be variadic, so with the groups spread out these tests could never take an options value at the end; with a slice, settings such as the centre of Levene's test or Welch's one-way ANOVA can be added later without breaking every call again.
- `FactorAnalysis` takes its options as an optional `opts ...FactorAnalysisOptions`, so `FactorAnalysis(dt)` runs with the defaults `DefaultFactorAnalysisOptions` returns. Calls that pass one options value compile unchanged; code that stored `stats.FactorAnalysis` in a variable of the old function type has to change the type.
- Every hypothesis test's result exposes the part they share. The struct holding `Statistic`, `PValue`, `DF`, `CI` and `EffectSizes` is exported as `TestResult`, and the new interface `HypothesisTestResult`, with one method `Base() *TestResult`, is satisfied by `TTestResult`, `ZTestResult`, `FTestResult`, `ChiSquareTestResult`, `CorrelationResult`, `WilcoxonTestResult`, `MannWhitneyUResult`, `KruskalWallisResult` and `FriedmanTestResult`. One function, or one slice, can now take a t-test, a Mann-Whitney U test and a chi-square test alike and read `r.Base().PValue`; the struct used to be unexported, so there was no type to name. Field access such as `r.PValue` is unchanged.
- **BREAKING**: a result field that only some tests fill is a pointer that is `nil` when it does not apply, and one every test fills is a plain value; the tests used a pointer, `NaN` or 0 for the same thing. `TTestResult.Mean` is now a `float64`, as `ZTestResult.Mean` already was, and `PairedTTest` fills `Mean` and `Mean2` with the means of `data1` and `data2`, and `N2` with the number of pairs, where it left them `nil`. `WilcoxonTestResult.Z` and `MannWhitneyUResult.Z` are `*float64`, `nil` on the exact path instead of `NaN`. `FTestResult.DF2` is `*float64`, `nil` for `BartlettTest`, which reported 0, a number that could be passed on to an F distribution. Write `r.Mean` instead of `*r.Mean` for a t-test, and `*r.Z` or `*r.DF2` where you read those fields. Passing `r.Z` or `r.DF2` to `fmt` still compiles but now prints a pointer. Every number the tests report is unchanged.
- **BREAKING**: `TwoSampleTTest` takes its variance assumption in `TTestOptions` as `EqualVariance`, and leaving it out runs Welch's t-test, as R's `t.test` does by default. The positional `equalVariance bool` is gone: `TwoSampleTTest(a, b, false)` becomes `TwoSampleTTest(a, b)`, and `TwoSampleTTest(a, b, true)` becomes `TwoSampleTTest(a, b, stats.TTestOptions{EqualVariance: true})`. A bool no longer fits where the options go, so an old call fails to compile rather than changing meaning, and a rewritten call returns what it returned before. Welch's test gives almost the same answer as Student's when the two variances are equal and stays valid when they are not, which is why it is the one you get without asking.

### `csvxl`
- **BREAKING**: `ExcelToCsv` and `EachExcelToCsv` check a name given in `csvNames` the way v0.3.3 already checked a name made from a sheet: one holding a path separator, or one that would not land directly inside the output directory, is refused, so `csvNames: []string{"sub/out.csv"}` no longer writes into a subdirectory. The error used to say only "2 files failed to convert", each failed file left an empty sheet in the workbook, and `AppendCsvToExcel` emptied an existing sheet of the same name before finding out its CSV could not be read, then saved the workbook. On the reading side, `CsvToExcel` and `AppendCsvToExcel` open a path as written when it names a file and append `.csv` only when nothing is there: a CSV called `export.txt`, `DATA.CSV` or with no extension at all used to be unreadable, because `.csv` was appended to every path not ending in lowercase `.csv`, and now it reads. - **BREAKING**: `ExcelToCsv` and `EachExcelToCsv` guard formula-like text by default, as `ToCSV` does: text that is safe inside a workbook becomes a formula again in a CSV opened in a spreadsheet. `ExcelToCsvOptions{AllowFormulas: true}` writes it exactly. The sheet list moved into the same options: `ExcelToCsv(file, dir, names, "2024", "2025")` becomes `ExcelToCsv(file, dir, names, csvxl.ExcelToCsvOptions{Sheets: []string{"2024", "2025"}})`.
- **BREAKING (output)**: `AppendCsvToExcel` replaces an existing sheet with a fresh one, the way `DataTable.ToExcel` does, instead of clearing its cells in place as v0.3.3 did. Clearing removed values and formulas but kept whatever else the rows and cells carried: a new row landing on an old hidden row was invisible in Excel and was skipped when `ExcelToCsv` read the sheet back, and old comments and hyperlinks stayed on the new values. It was also slower the more the old sheet held: replacing a sheet of 20,000 formulas took 157 ms, and takes 6 ms now. The sheet keeps its position and stays hidden if it was hidden, the active sheet stays the same, and names and formulas elsewhere in the workbook are kept, but the old sheet's column widths, views and merged ranges are no longer kept, and neither are the names defined for that sheet alone. A sheet found under a name that differs only in case now takes the name as given: appending to `TARGET` renames a sheet called `Target`, which v0.3.3 left as it was.

### `parquet`
- `Write` writes to a temporary file and renames it into place, so a failure part-way cannot leave a truncated Parquet file.
- `Write` writes a column of `[]byte` cells as an Arrow `Binary` column, so a binary column read with `Read` and written back keeps its bytes and its type. v0.3.3 wrote such a column as a string column holding Go's text for each slice, such as `[65 45 48 49]`.

A bare target is a column letter (`A`, `B`, ... `AA`) and nothing else, where it used to fall back to a column of that name whenever the letters landed past the end, so `score = A * 2` on a file with a column named `score` worked here and failed there. Write `['score'] = A * 2`, and the failure now says so when the file has a column of that name.
- **BREAKING**: `Stream` returns `iter.Seq2[*insyra.DataTable, error]` instead of two channels, so it is used as `for dt, err := range parquet.Stream(ctx, path, opt, 1000)`. Leaving the loop early stops the reader. With the channels, a caller who broke out of the loop without cancelling its context left the reading goroutine parked on its next send for the rest of the process, and the documentation's own example raced the two channels against each other. Each batch arrives with a nil error; a failure arrives once, as a nil table and the error, and ends the loop; cancelling `ctx` ends it with the context's error.

### Core

- Fixed ordering losing precision on integers. Every integer was compared through `float64`, so any two `int64` above 2^53 looked equal and `Sort`, `SortBy`, `Pivot` and `Describe`'s min/max ordered them wrongly. Integers now compare exactly, including mixed signed/unsigned and values past `int64`.
- Fixed `HermiteInterpolation` using the wrong basis: it satisfied none of the derivative conditions it is named for. It now passes through every value and matches every supplied derivative, and reproduces low-degree polynomials exactly.
- `TryParseTime` accepts the common layouts that carry no zone — `2006-01-02 15:04:05`, `2006-01-02T15:04:05` and `2006-01-02 15:04`, plus `2006/01/02 15:04:05` and `2006/01/02 15:04` (a `/`-separated date takes no `T`) — read as UTC. CCL's date functions and `datafetch` were silently treating those strings as text.
- Fixed `ShowTypes` printing columns as `A, AA, AB, B, …` past column 26, with or without column names; it now uses the same order as `Show`. `ShowRange`'s documentation now states the rule the code implements: the end index is exclusive and a negative end counts back from the end and stays exclusive, like a Python slice, so pass `nil` to run to the end.

- Fixed `DataList.ReplaceLast` replacing the last `NaN` cell instead of the last cell equal to `oldValue` when the list ended in `NaN` (`[5, NaN].ReplaceLast(5, 0)` gave `[5, 0]`).
- Fixed `ReadJSON_File` loading integer literals as `float64` while `ReadJSON` loaded them as `int64`; both now decode through the same path, so large integers keep full precision from a file and a file holding a single object loads as one row.
- Fixed several `DataTable` behaviours found by the API review: `GetElementByNumberIndex`, `SetRowToColNames`, and `SetColToRowNames` no longer panic on an out-of-range index (they set `Err()`), and `GetElementByNumberIndex` accepts a negative column index; a `Filter*` call with no match returns an empty table whose methods are safe to call; `FilterRows`/`FilterCols` no longer panic on a ragged table; `DropRowsByIndex` resolves negative indices against the original row count and ignores duplicates (`(-1, 0)` used to keep row 0, `(1, 1)` used to delete two rows); `Transpose` keeps every row name (names beyond the old column count were lost); `AppendRowsByColIndex` grows the table to the addressed column instead of dropping the value; `DropColsContainNumber`/`DropRowsContainNumber` recognise every built-in integer and float type (an `int64` column from CSV inference was not dropped), while a named numeric type such as `time.Duration` is still kept; and `Mean` divides by the number of numeric cells.

The error hook installed by `SetDefaultErrHandlingFunc` runs on one goroutine behind a queue of 1,024 calls, in order, instead of one goroutine per warning; a call that finds the queue full still reaches the hook, on its own goroutine and possibly out of order. - CCL: `NULL`, `TRUE` and `FALSE` are keywords in any case instead of column references; `@` used as a value gives each row its own slice (every cell used to show the last row); a sequence function inside another sequence or aggregate function (`LAG(LAG(A,1),1)`, `SUM(LAG(A,1))`) keeps the whole column; a `LAG`/`LEAD`/`ROLLING_*` shift or `REPEAT` count that is `NaN`, infinite or beyond `int64`, and a `REPEAT` result whose length overflows `int`, are errors instead of panics, while a shift or window longer than the column still gives `nil` cells; the function registry is safe to extend while another goroutine evaluates; `engine/ccl.NewMapContext` orders columns by name so `A`/`B` are deterministic.

Before, only UTF-8, UTF-16, Big5 and GB18030 had a decoder: `iso-8859-1`, which the detector names correctly, was copied into the table as cells that are not valid UTF-8, and `utf-16be` without a byte-order mark was read as little-endian. - CCL failures say which phase failed and where. A compile failure names the expression, the byte offset of the problem and the text at it (`cannot compile "(A B)" at offset 3 (near "B"): expected ')'`); an evaluation failure names the row (`cannot evaluate "A / B" at row 1: division by zero`), or says nothing about rows when the expression does not depend on one. `AddColUsingCCL`, `EditColByIndexUsingCCL` and `EditColByNameUsingCCL` used to report both under the prefix `Failed to apply CCL on DataTable after 213.792µs`, which answered neither question and put a stopwatch reading where the cause belonged. `position N` used to mean a byte offset in one place and an index into the token list in another; it is always a byte offset now, snapped to a character boundary so a non-ASCII expression points somewhere real. Two messages printed Go internals (`unexpected token: {5 )}`, `invalid range operands: &{: 0x1d48…}`) and now print the source text. A failure inside `ExecuteCCL` names the statement it came from, so a script of five lines no longer reports `Failed to execute CCL statement: division by zero` with nothing to say which line produced it. The failures are exported types — `ccl.CompileError` and `ccl.EvalError` from `engine/ccl` — and `ErrorInfo` gained a `Cause` field and an `Unwrap`, so `errors.As(dt.Err(), &compileErr)` works instead of matching on message text. `Unwrap` returns nil for the nil `*ErrorInfo` that `Err()` gives after a call that succeeded, so that check does not panic on a formula that worked. They are still recorded as warnings, like every other `DataTable` error.
- CCL no longer repeats work whose answer cannot change. In `AddColUsingCCL`, `EditColByIndexUsingCCL` and `EditColByNameUsingCCL`, an aggregate that does not mention `#` is computed once before the rows are walked, though not ahead of a table with no rows, instead of once per row over a fresh copy of the column: on 20,000 rows `A / SUM(A)` goes from 2.1 s to 1.0 ms, and the z-score `(A - AVG(A)) / STDEV(A)` from 6.2 s to 1.8 ms. An aggregate that does mention `#` is row-dependent and still runs per row. Three smaller costs on the same path: a string is only offered to the date parsers when its first character could start a date, `REGEX_MATCH` compiles each pattern once instead of once per row, and `ROLLING_*` converts its column once rather than once per window per element. **No result changes**, and `ROLLING_*` stays proportional to the window on purpose, because a running accumulator would drift where recomputing the window does not.
- `AtomicDoAll` skips a nil instance, whether a nil `*DataList`, a nil `*DataTable` or a nil value, instead of panicking; the instances next to it are still locked.
- Fixed `GroupBy` computing from the parent's data as it was when `Aggregate` ran rather than when the groups were formed. It kept pointers to the parent's columns, so a change to the parent between the two calls reached the result (a group holding `3` summed to `102`), and `Aggregate` read that data without a lock while another goroutine could be writing it. `GroupBy` now copies the column data it groups.
- Fixed searching, counting, replacing and dropping by value missing an integer stored as another Go integer type. A CSV load stores integers as `int64` while Go code writes `2` as `int`, and the comparison used `==`, which never matches an `int64` against an `int`: on a table read from CSV, `Count(2)` returned 0, `FindAll(2)` and `FindRowsIfContains(2)` found nothing, and `Replace(2, 0)` changed nothing. Integers now match by value, from `int8` to `int64` and `uint8` to `uint64`, in `Count`, `FindFirst`, `FindLast`, `FindAll`, the `Replace` methods, `DropAll`, `FindRowsIfContains(All)`, `FindColsIfContains(All)`, `DropRowsContain` and `DropColsContain`. A float still never matches an integer, so search with `2.0` to find `2.0`, and floats, strings, bools, `nil` and `NaN` match exactly as before. `IsEqualTo` and `IsTheSameAs` still compare type by type. These lookups also no longer panic on a cell Go cannot compare with `==`, such as a struct holding a slice; it is matched by its type and content. Searching for a float or a string is faster, because the comparison for the searched value's type is now picked once per call: a `Count` over a million cells went from 2.3 ms to 1.7 ms for floats and from 2.8 ms to 2.0 ms for strings.
- Fixed CCL giving a different answer on amd64 and arm64 when a count, digit count or date shift was too large for Go's conversion to an integer or a duration, which is undefined there. On Linux and Windows `MID('abc', 2, 10^300)` returned `""` while a Mac returned `"bc"`, `ROUND(x, NaN)` returned `NaN` on one and rounded to an integer on the other, and `DATEADD(d, 10^300, 'day')` produced a different wrong date on each. A character count or position past the end of a string now means "to the end" everywhere. A `NaN` count or digit count, a `DATEADD` day, month or year count that is infinite or beyond `int64`, or of more than about 292 years in hours, minutes or seconds, a date plus or minus more than 106,751 days, a `DAY`, `HOUR`, `MINUTE` or `SECOND` of more than about 292 years of seconds, and a row range bound that is `NaN` or outside the int32 range are errors instead of a wrapped-around value. Results for ordinary values are unchanged, including the conversions that drop a fraction, such as a fractional `DATEADD` day count.
- Fixed `Show` (and every other display path) printing a different number on amd64 and arm64. The formatter decided whether a float was a whole number with `v == float64(int(v))`, and that conversion is undefined in Go for a value outside `int`'s range: `2^63` printed as `9223372036854775807` on a Mac — an exact-looking integer one less than the value — and as `9.2234e+18` on Linux and Windows. Anything outside `int64`'s range now takes the exponent form everywhere. Whole numbers inside the range are unchanged.
- Fixed a Unix timestamp in milliseconds reading as the wrong date past 2262-04-11. The conversion multiplied the value into nanoseconds first, which overflows `int64` well inside the range it accepts, so `99999999999999` came back as 2216 instead of 5138.
- Fixed six values that came back wrong with nothing to show for it. A 16-digit (microsecond) timestamp read as seconds, so `2023-11-14` became `53872825-06-17`; the millisecond window also stopped short of the microsecond one, leaving a range that fell through to seconds. `CalcColIndex` produced column names its own `ParseColIndex` refused at the very top of the `int` range. `Show` printed `9999.99999` as `10000` — rounded to four places and trimmed of its trailing zeros, which reads as an exact integer. `IsNumeric` and the numeric read path disagreed about every named type over a numeric kind (`type Celsius float64`, `time.Duration`): `IsNumeric` called such a cell a number while `ToFloat64Safe` refused it and `ToFloat64` gave `0`, so `Mean` and `Sum` skipped it and `ToF64Slice` turned it into `0`. Both now read its value (a `time.Duration` reads as nanoseconds). `DataList.NearestNeighborInterpolation` answered the first value for a `NaN` x — every comparison against NaN is false, so the search never moved — and `LagrangeInterpolation` and `NewtonInterpolation` returned `NaN` with nothing in `Err()`; all three now return `NaN` and record the failure in `Err()`, like `LinearInterpolation` and `QuadraticInterpolation` already did.
- Fixed two tables with no column names failing to merge vertically. `NewDataTable(NewDataList(...))` leaves every column unnamed, and the duplicate-name check counted the empty name as a duplicate of itself, so the plainest constructor produced a shape that could not be merged with another of its kind. Unnamed columns now line up by their position among the unnamed ones; named columns still line up by name.
- CCL: a number literal too large for a `float64` is an error instead of silently becoming `+Inf` — `strconv.ParseFloat`'s error was being dropped. Exponent notation is now a literal form: `1e5`, `1.5e-3` and `2E+3` compile, where they used to split into a number and an identifier and fail with `unexpected token`, even though `VALUE('1e3')` always worked and CCL's own string output uses exponent form. An `e` only joins the number when a digit follows, so a column called `E` or `E1` is unaffected. `TOSTR(1.5, '%d')` and `TOSTR(1, '%')` report the mismatch instead of writing Go's own complaint — `%!d(float64=1.5)`, `%!(NOVERB)` — into the cell. Text that only looks like such a complaint because it was already in the value or the format, such as `TOSTR(A, '%s')` on `Item (MISSING)`, is written as it is.
- `Show` and every other display path print a struct value that implements `fmt.Stringer` as its text. The formatter ended in a branch that printed `<pkg.Type>` for a struct without asking whether it could print itself, so a Parquet decimal column showed as `<decimal.Decimal>` in every row. A struct without `String()` still shows its type name, a nil pointer still shows `<nil>`, and the stored value is unchanged.
- A string cell that is not valid UTF-8 is displayed as hex, the way a `[]byte` already was, instead of as quoted mojibake. Beyond being unreadable, the quoted bytes put the row one column out of alignment: `runewidth` scores a NUL at 0 and an invalid byte as one `U+FFFD`, while a terminal draws them however it likes, so no width calculation could be right. Such a string now renders as `00ff41`, truncated past 20 bytes with a count, which is ASCII, so the column lines up. Valid UTF-8 is untouched, CJK and emoji included, and the stored value does not change.
- `Counter` no longer panics on a cell value Go cannot use as a map key, and the lookups agree with it. `Counter` built a `map[any]int` keyed by the cell, so a value that cannot be hashed took the process down, while `Count`, `FindAll`, `Replace`, `DropAll`, `IsEqualTo`, `IsTheSameAs` and the `DataTable` find and drop methods treated it as unequal to everything, so `Count` reported 0 for a value sitting in two rows. This is reachable without trying: `ReadSQL` keeps a binary column as `[]byte` on purpose (BLOB, BYTEA, BINARY, VARBINARY, LONGBLOB). Such a value is now identified by its type and content: `[]byte{0, 255}` matches another `[]byte{0, 255}` but not a `[]int{0, 255}`, and integers nested inside it compare by value, as `Count` does. `Counter` keys it by the new `insyra.UncomparableKey`, which the new `insyra.ToMapKey(v)` builds for a caller indexing the whole map or keeping a map of their own over cell values; comparable values are still keyed by themselves, so `counter[1]` is unchanged, and a printed stand-in shows its type and a shortened form of its content, such as `[]uint8(00ff41)`. To read one value's count prefer `Count`, which matches integers by value where the map keys them by Go type. A scalar `NaN` cell is still unequal to another `NaN` in `IsEqualTo`; inside a slice, map or struct a `NaN` is part of the content, so two `[]any{NaN}` cells are equal and match each other. `GroupBy`, `Pivot`, `Merge` and `Describe` keep their existing keys.
- `insyra.Cell(v)` keeps one value in one cell when a constructor would otherwise flatten it. `NewDataList` flattens slices on purpose, so that building a list reads the way building a pandas Series does, and there was no way to opt one argument out short of leaving the constructor for `Append`, which cannot be mixed into the same call. `NewDataList(insyra.Cell([]int{1, 2}), 3, "a")` is three cells, and the first holds the slice at its own type. Every entry point that takes a value from the caller accepts the mark and removes it — `Append`, `Update`, `InsertAt`, the `Replace` and `Replace…With` methods of `DataList` and `DataTable`, `Shift`'s fill value, `UpdateElement` and the row appenders — including the ones that never flatten, so `Append(Cell(x))` and `Append(x)` mean the same thing; `Count(Cell(x))` and `Count(x)` agree too. A bare slice still flattens.
- An `insyra.UncomparableKey` prints the way the value writes itself. It rendered the encoded content, which for a struct is its fields, so an uncomparable value implementing `fmt.Stringer` showed its internals in a printed `Counter` result: a `decimal.Decimal`, what a Parquet `Decimal128` column reads as, printed its `big.Int`'s sign and words. Such a value now shows its own text, such as `decimal.Decimal(-340.0221114815)`, truncated by the same limit; a value without `String()` is unchanged. Identity still comes from the encoding, not the text, because a `String` may be lossy and two distinct values whose text matched must not merge into one count.
- Fixed `SortBy` mishandling a column that is not there. A missing index, name or number was reported by the internal `GetCol`, `GetColByName` or `GetColByNumber` lookup instead of `SortBy`, and a multi-level sort with one bad level still applied the others. Every level is now checked before any row moves, and a missing column records the error on `SortBy` and leaves the table unchanged. A config giving more than one of `ColumnIndex`, `ColumnName` and `ColumnNumber` still sorts by the documented precedence (index, then name, then number) and now logs a warning naming the fields it ignored; `Err()` stays nil. A config that gives none still sorts by the first column, and `Docs/DataTable.md` now says so: `ColumnNumber` counts only when it is not zero, so its zero value never overrides a name or an index.
- `engine/biindex`: `BiIndex.Set` moving a name onto another id now frees the name's old id, so a later `Assign` hands it out again. The old id used to be deleted without being freed, leaving a hole no `Assign` could reuse.
- CCL: a date plus or minus a number of days keeps the part of a day below an hour, which is what `Docs/CCL.md` has always said: the number counts days. The days were cut to whole hours, so `A + 0.0625` moved the date 1 hour instead of 1 hour 30 minutes and `A + 0.001` did not move it at all; they now move it 1 hour 30 minutes and 86.4 seconds. Whole and half days move exactly as before.
- CCL: comparing a string that is not a number with a number using `>`, `<`, `>=` or `<=` is an error, which is what `Docs/CCL.md` has always said (`"hello" > 5 // Error`). It returned `false`, so `A > 5` on a row where `A` held a word read as an ordinary answer. `==` and `!=` still report such a pair as unequal, a numeric string such as `'5'` still compares as a number, `nil` still compares as `false`, and two strings that are not both numbers still compare as `false`. A string CCL reads as a date (`'2024-01-02'`, RFC3339) and an empty string are not words: they compare as `false`, the way they always have, so `A > 0` over a date column loaded from CSV or Excel and `A > 5` over a column with a blank in it still produce a column.
- CCL: `AND()` and `OR()` report an argument they cannot read as a boolean instead of counting it as `false`, matching `&&` and `||`, which `Docs/CCL.md` calls the same operation. `AND('abc', TRUE)` answered `false` — indistinguishable from a real comparison — while `'abc' && TRUE` reported the word. Everything the conversion does read is unchanged: a number (`0` is false), `nil`, and the strings `true`/`yes`/`1`/`false`/`no`/`0`/`''`. So is the argument count (`AND()` is still `true`, `OR()` still `false`) and the short-circuit: `AND()` stops at the first false and `OR()` at the first true, so an argument they skip is never read and `AND(B != 0, A / B > 1)` still guards the division.

Twenty-one places across `ttest`, `ztest`, `anova`, `chisq`, `movavg`, `expsmooth`, `shift`, `diffn`, `pctchange`, `rolling`, `expanding`, `ewm`, `quartile`, `percentile` and `fetch` read the same way now. ### `stats`

- `KMeans` picks distinct initial centres, as R does. On data with repeated rows a single-start run used to draw the same row twice and fail with "empty cluster" — 44 of 50 seeds in one measured case. A colliding draw is now redrawn from the distinct rows; a draw that was already distinct is untouched, so every existing seeded result is bit-identical.
- Functions taking `insyra.IDataList` no longer panic on a `nil` argument or on an implementation other than `*insyra.DataList`; the value is converted and a `nil` is reported as an ordinary error.
- `FactorAnalysisResult.RotationConverged` reports whether the rotation converged. It was always `true`: the candidate chosen among restarts never carried the flag, so `fa.Rotate` fell back to its default — a rotation stopped after one iteration at a tolerance of 1e-12 still reported convergence. The flag now describes the solution that is returned, and picking among restarts prefers a solution that converged, falling back to the best criterion value and reporting `false` when none did.
- A rotation that did not converge logs one warning per search, naming the method, the number of starts and the iteration cap, and only when the solution it returns did not converge — the case `RotationConverged` reports as `false`. `GPForth` and `GPFoblq` used to warn on every start that hit the cap, and the Varimax start a multi-start search builds warned too, so a call with `Restarts` above 1 could log several warnings and push as many entries into the global error buffer while the returned solution had converged; those runs now report at debug level only.
- `Skewness` and `Kurtosis` refuse a value they cannot read as a finite number instead of reading it as zero, which is what the `stats` documentation has always said of every numeric entry point. A blank, text, `NaN` or `Inf` cell is an error naming `sample` and the one-based row: `Skewness` of `[1, nil, 3, 4]` returned `0` and `Kurtosis` of `[1, "x", 3, 4]` returned `-1.64`. As documented, a string is refused even when it spells a number. Results on fully numeric input are unchanged.
- `SingleSampleTTest`, `TwoSampleTTest`, `SingleSampleZTest`, `TwoSampleZTest`, `FTestForVarianceEquality`, `BartlettTest`, `LeveneTest` and `CalculateMoment` refuse a cell they cannot read as a finite number, naming the series and the one-based row, which is what the `stats` documentation has always said of every numeric entry point. The tests took `n` from the list length while the mean and standard deviation skipped the unreadable cell, so `[1, 2, nil, 3]` reported t = 4.00, p = 0.028 instead of the t = 3.46, p = 0.074 of `[1, 2, 3]`: a blank turned an insignificant result significant. `CalculateMoment` read such a cell as zero, and `LeveneTest`, which already refused it, now names the row the same way. A `nil` list, typed or not, is an error instead of a panic in `SingleSampleTTest`, `SingleSampleZTest` and `CalculateMoment`. Results on fully numeric input are unchanged; clean blanks with `ClearNils` before testing.
- `FactorAnalysis` with `Rotation.Restarts` above 1 returned loadings that no longer described the fitted model. A rotation criterion is minimised over a constrained set — `T'T = I` for the orthogonal family, `diag(T'T) = I` for the oblique one — and the gradient projection algorithm only keeps an iterate on that set if the start is on it. Two of the starting points added when `Restarts > 1` were Promax and Target rotation matrices, which are oblique, so whichever start won on criterion value decided whether the answer was a rotation at all. Measured over the 20 datasets of the factor-analysis suite and all four extractions, `max|L·Φ·L' − Lu·Lu'|` reached 0.766 at `Restarts >= 2` and is now at most 2.4e-15. Every start is now orthogonal — the identity, the Varimax solution, then QR-orthogonalised random matrices, which is what `GPArotation::Random.Start` produces for both families — and is verified before use. `Restarts` now also means the number of starts: it used to bound only the random ones while three heuristics were added unconditionally, so `Restarts: 2` ran four. **Results at `Restarts >= 2` change**, by up to 2.04 per loading, because what they returned was not a rotation of the fitted model; Oblimin and Promax are unaffected, the first because it ignores its starts and the second because it runs from one. Results at the default `Restarts: 1` are unchanged, bit for bit over all 800 dataset/extraction/rotation combinations measured.
- `FactorAnalysis` with `Rotation.Restarts` above 1 runs from the same random starts on every platform. The random starts were seeded from a hash of every bit of the unrotated loadings, and extraction does not reproduce those bits across architectures: four factors fitted by ML to a 60-row synthetic table differ in the eighth decimal between amd64 and arm64. The two drew unrelated starts, so the same call could return a solution in a different basin. Measured over the 20 datasets of the factor-analysis suite and all four extractions, 197 of the 2400 `Restarts >= 2` combinations disagreed between an arm64 run and the same run under `GOARCH=amd64`, the worst of them by 2.1 per loading; with a fixed seed the only remaining disagreements are the 8 combinations that already differ at `Restarts: 1` by 1.5e-5 or less, which is extraction noise rather than a different solution. On data whose rotation criterion has more than one minimum, a multi-start result can differ from before on every platform, because the random matrices are different ones — measured at up to 2.15 per loading for simplimax. `Restarts: 1` is unchanged, bit for bit over all 800 dataset/extraction/rotation combinations, and the strict R parity suite reports the same 1,842 failing leaves with the same numbers before and after.

### `csvxl`

- Fixed `AppendCsvToExcel` leaving the old sheet's cells in place when a sheet of the same name already existed: `excelize.NewSheet` returns the existing sheet, so only the cells covered by the new CSV were overwritten and the rest survived. The existing sheet is now cleared in place before the CSV is written, so no old cell or formula survives while the sheet keeps its position and its settings such as column widths, including when it is the workbook's only sheet.
- Fixed `AppendCsvToExcel`, `ExcelToCsv`, and `EachExcelToCsv` never closing the workbooks they opened.
- Errors wrap their cause with `%w` (so `errors.Is(err, os.ErrNotExist)` works) and output directories are created with mode 0755 instead of 0777, so on a system with umask 0002 they no longer give the group write permission.
- `ExcelToCsv` and `EachExcelToCsv` reject a CSV file name that would not land directly inside the output directory, such as one made from a sheet named `../x` or `a/b`, which a crafted workbook could use to truncate a file outside it. Only a name made from a sheet name is checked, so a `csvNames` entry is used as given, and a sheet named `.` or `..` still converts. Each sheet is read before its CSV is created, and a write error at the final flush is returned.
- `ReadCsvToString` returns UTF-8 content or an error, which is what its documentation has always said. For an encoding nothing decodes, whether passed by name or reported by `Auto` (ISO-2022-KR, ISO-2022-CN, IBM424, IBM420), it returned the file's raw bytes, which are not valid UTF-8, with a nil error; it now returns an error naming the supported encodings. A name in the decoder table or matched by the older substring rules (`big5-hkscs`, `utf-8-sig`) reads as before, in any case: the substring rules used to be matched on the name as typed, so `UTF-8-SIG`, `Utf-8-Sig`, `BIG5-HKSCS` and `X-GBK` were refused while their lower-case spellings read, and `ReadCSV_File`, which lower-cases the name first, disagreed with `ReadCsvToString` about the same file. The "unsupported encoding" error now also names the four substring families (`utf8`, `big5`, `gb`, `utf16`), not only the table's normalised keys. `CsvToExcel`, `AppendCsvToExcel`, `EachCsvToOneExcel` and `ReadCSV_File` still read an unknown encoding undecoded.

### `parquet`

- Fixed `ReadColumnOptions.MaxValues` having no effect. `ReadColumn` now sums the row counts of the selected row groups from the file metadata and refuses the read before loading anything when the count exceeds the limit, which is what the field documented.
- `Write` returns the error from closing the Parquet writer instead of only logging it. The footer is written on close, so a failed close used to leave an unreadable file behind a `nil` error. Close-time errors elsewhere in the package are logged through Insyra's logger instead of the standard `log` package, so `Config.SetLogLevel` applies to them.
- Fixed `FilterWithCCL` returning only the first 1000 matching rows. The file is read in batches of 1000, and every batch after the first was appended to a copy of the result column rather than the column itself, so a 2500-row file filtered on a condition every row satisfies came back with 1000 rows and no error at all. Matching rows are now collected across the whole stream.
- A read error that arrives after the last batch is no longer traded for a partial answer. The reader's record and error channels are closed together, and the `select` in `FilterWithCCL`, `ApplyCCL` and `Stream` could pick either, so a file that failed to read part-way could return a truncated table with a nil error — and in `ApplyCCL`'s case overwrite the original file with the truncated result. All three now read the error channel before finishing. A successful streaming call also stops logging `failed to close file … file already closed`, which it printed every time.
- Reading a Parquet file written by another tool no longer turns a column type the reader did not handle into one repeated string. `getVal`'s fallback returned `arr.String()`, the string form of the whole array, ignoring the row index, so every row of such a column read back as something like `[19000 19001 19002]` with `Read` returning a nil error and the table's `Err()` nil. `parquet.Write` emits only seven Arrow types, so this was invisible on files this library wrote and hit everything else. Now `Date32`/`Date64` read as `time.Time` at UTC midnight, `Int8`/`Int16` and the four unsigned widths as their own Go types, `LargeString` as `string`, and `Decimal128`/`Decimal256` exactly, as a [go-decimal](https://github.com/TimLai666/go-decimal) `decimal.Decimal` built from the file's own unscaled integer and scale. Anything left — `List`, `Struct`, `Map`, `Time32`, `Time64`, `Duration`, `Interval` — reads as `nil` cells, and the rest of the file still reads. `Read`, `Stream` and `ReadColumn` log the reason as a warning and record it on the returned table's or list's `Err()`, as `column "tags": unsupported Arrow column type list<item: int64>; its cells were read as nil`; when several columns are affected, each is logged and `Err()` names the last. `FilterWithCCL` sees `nil` for such a column too, without recording a reason. `ReadOptions.Columns` can skip the column. A column of Arrow type `Null` reads as `nil` cells with no reason recorded, since that is all it holds. A dictionary-encoded column reads as the Go type of its values, whether the reader materialises it or, for a file that stores its Arrow schema, hands it over as an Arrow dictionary.
- A `decimal.Decimal` sorts by value rather than by the lexicographic order of its digits, so a column holding 9.5, 10.2 and 100.0 sorts in that order rather than 10.2, 100.0, 9.5. Like `time.Time`, it is not numeric to `Mean`, `Sum` or `IsNumeric`.
- A Parquet `Binary`, `LargeBinary` or `FixedSizeBinary` column reads as `[]byte`. Every row used to hold the same text, the string form of the whole array, with a nil error, so the bytes were lost and a binary column read back like a text one. Each cell now holds its own bytes, copied out of Arrow's buffer, in `Read`, `Stream` and `ReadColumn`. `Show` prints the column as hex, and JSON export writes it as base64. `Write` still writes a column of `[]byte` cells as a string column, holding Go's text for the slice such as `[65 45 48 49]`, so writing such a column back does not keep its bytes.

## v0.3.1

### Core

- Added `CSVReadOptions` together with `ReadCSV_FileWithOptions` and `ReadCSV_StringWithOptions`. Setting `RawStrings` keeps every cell as its original string and skips column-level type inference, so values like stock IDs no longer lose their leading zeros and empty cells stay `""` instead of becoming NaN. `ReadCSV_File` and `ReadCSV_String` keep their existing signatures and behavior.

### `isr`

- `CSV_inOpts` gains a `RawStrings` field, which `DT.From` passes through to the reader.

### `accel`

- Large `nn` 2-D float32 MatMuls now have a default-on device path through `accel.DeviceMatMul`. It preserves each output's serial `k` accumulation order, records fallback reasons through the existing `accel` report, and leaves the exact CPU path in charge when no device is available or the backend fails. `INSYRA_ACCEL_DISABLE_WGPU=1` disables the backend.
- The wgpu backend is upgraded to v0.30.35, which fixes the upstream Metal checkptr abort — `go test -race` now covers the whole device path instead of skipping it, and the race guards are removed. Device numeric parity is unchanged across the upgrade.
- `accel` now executes on real hardware. `ExecuteDataList`, `ExecuteDataTable`, and `ExecuteProjectedDataset` return the computed value per column in `ExecutionResult.Reductions`, along with measured `Transfer`, `Dispatch`, and `Readback` durations and `BytesUploaded`.
- `accel.Session` is now safe for concurrent use. Every public method is serialized behind a session lock, so several goroutines can share one session; previously concurrent `ExecuteDataList` calls raced on the cache and report state. Device submission is also serialized process-wide, because all sessions share one GPU handle.
- Added `accel.Default()`, a session shared by the process and created on first use. Discovery runs once, the resident cache is shared across operations, and `Close` on it is a no-op because no caller owns it. Importing the package still opens no device.
- Added `accel.OpSquaredDistance` with `Session.ExecuteDistances`, computing the squared Euclidean distance from every row to each query point on a GPU, and `accel.SquaredDistancesCPU` as its reference. Device results are verified bit-identical to the reference on the running platform.
- Added `accel.OpNearestQuery` with `Session.ExecuteNearestQuery` and `accel.NearestQueryCPU`, reporting the closest query point per row and its squared distance. The minimum is taken on the device, so the result grows with rows rather than with rows times queries — 13.6x over the CPU at 64 query points on an Apple M3. Ties go to the lowest query index.
- `accel` is now part of `allpkgs`, so the standard `go get .../allpkgs` install registers the GPU backend automatically. Registration is lazy — no device is probed until an accel session opens.
- GPU execution is builtin. The backend is a pure-Go WebGPU implementation ([gogpu/wgpu](https://github.com/gogpu/wgpu)) that registers itself when `accel` is initialised, so there is nothing extra to install and nothing to import for a side effect. It builds with `CGO_ENABLED=0` and reaches Metal on macOS, Vulkan on Linux and Windows, and DirectX 12 on Windows. Programs that never import `accel` compile none of it, though the gogpu modules do appear in `go list -m all`. Set `INSYRA_ACCEL_DISABLE_WGPU=1` to turn it off without changing code.
- **Breaking:** `BackendAllocator`, `RegisterBackendAllocator`, `AllocationRecord`, and `AllocatorKind` are replaced by `BackendExecutor`, `RegisterBackendExecutor`, `ExecuteRequest`/`ExecuteResponse`, and `ExecutorKind`. The old seam could not carry an operation or return a value, so no real backend could implement it.
- **Breaking:** `ExecutionResult.Allocator` and `ExecutionResult.AllocatorKind` are now `Executor` and `ExecutorKind`; `ExecutionResult.BytesMoved` is gone. It was derived from fixed per-backend constants rather than measured, so it is replaced by `BytesUploaded` and the three measured durations.
- GPU execution requires an explicit precision opt-in. WGSL has no `f64` and Apple GPUs have no double-precision hardware, so a `float64` column is not narrowed unless `WorkloadEstimate.Precision` is set to `accel.PrecisionFloat32`. Without it the workload falls back to the CPU with reason `precision-not-accepted`.
- Added fallback reasons `no-backend-executor`, `precision-not-accepted`, `dtype-not-eligible`, `shader-compile-failed`, `buffer-too-large`, `readback-timeout`, and `execution-failed`.
- A backend-reported CPU or software adapter is never treated as an acceleration device, so a host with no GPU driver falls back to the CPU instead of running a software interpreter and calling it acceleration.
- Projecting a column is much cheaper. Dataset fingerprinting no longer renders every value to text before hashing it, and `projectValues` no longer dispatches through `reflect` per element — the old path heap-allocated once per value. On a 4 Mi `float64` column, projection went from 4,194,308 allocations to 4, `ProjectDataList` from 357 ms to 43 ms, and an end-to-end GPU column sum from 354 ms to 48 ms. Fingerprints are session-local, so the different hash values are not observable across runs.
- `ExecuteDistances` and `ExecuteNearestQuery` now return the result whether or not a device ran. Previously a host with no GPU got `Accelerated: false`, the reason `no-accelerator`, and an empty slice, leaving every caller to notice and call the CPU reference itself. The same applies when a device is present but fails, times out, or exceeds a buffer limit. `Accelerated` and `FallbackReason` still report where the work ran, so nothing becomes less observable. A request refused on its own terms — `precision-not-accepted`, `dtype-not-eligible`, `workload-unsupported` — still returns nothing, because computing it on the CPU would deliver exactly what the caller declined. Strict GPU mode still returns an error rather than a CPU result.
- Added `accel.OpNearestShortlist` and `Session.ExecuteNearestExact`, which returns the M nearest query points per row as exact `float64` values while still using a GPU for most of the work. The device ranks in single precision and returns a shortlist per row plus the distance of the best candidate it discarded; the host recomputes that shortlist in `float64` and decides, falling back to every query point for the rows where single precision could not separate the candidates. The answer equals `accel.NearestExactCPU` exactly, so no precision opt-in is required. Measured on an Apple M3 over 200,000 rows against a host using all eight cores: 2.5x at 16 dimensions and 3.4x at 64, both with 1024 query points, and slower than the host below roughly 2048 distance evaluations per row — where the runtime declines the device and reports `workload-not-profitable`. `ExactNearestResult.Rechecked` reports how many rows took the full path.
- The host side of `ExecuteNearestExact` now uses every core. Both the no-device path and the verification of a device shortlist are split across `GOMAXPROCS` above a work threshold; below it they stay on one core. On 200,000 rows by 16 dimensions with 1024 query points the path taken by a machine with no GPU went from 1.575 s to 306 ms. The device shortlist is also read row-major rather than candidate-major, so verifying one row no longer strides across the whole array.
- `ExecuteNearestExact` no longer panics when asked for nine or more neighbours on a host with a GPU. The shortlist width was clamped to the device's eight slots while the decision still indexed position `m-1`; the device is now skipped for requests it cannot serve, and the host answers instead. It also no longer trusts a shortlist whose single-precision distances overflowed to infinity — the ordering carries no information in that case, and the boundary test passed for the wrong reason. The error bound used to decide whether a shortlist can be trusted was widened to account for the rounding of the difference itself and for squared terms below the smallest normal `float32`.
- **Breaking:** `OpSum`, `OpSquaredDistance` and `OpNearestQuery` are removed, together with `ExecuteDataList`, `ExecuteDataTable`, `ExecuteProjectedDataset`, `ExecuteDistances`, `ExecuteNearestQuery`, `SquaredDistancesCPU`, `NearestQueryCPU`, their WGSL kernels, and the `accel run <var>` CLI command. Each was measured against a host using all its cores and lost: the column sum runs at 0.7x because it moves one value per element and adds it once; the distance matrix reads back a result that grows with rows times query points; and the single-precision nearest query answers in `f32`, which the `float64` callers it was built for cannot use. `ExecuteNearestExact` supersedes the last of these and returns the exact `float64` answer. None of the removed surface appeared in a release. `accel devices`, `accel cache` and `accel plan` are unaffected.
- Oversized `ExecuteNearestExact` submissions now run as sequential 16,000-row device chunks and merge in input order instead of losing the device to a readback timeout. The exact `float64` CPU decision is unchanged, submissions at or below the measured bound keep the single-submission path, and `ExecutionResult.Chunks` reports the number of device submissions.
- Added hard device selection for accel sessions. `INSYRA_ACCEL_DEVICES` masks devices at discovery and `Config.Devices` allowlists a session; the eligible set is their intersection, while `PreferredDevices` remains a soft ordering within it. IDs and zero-based discovery indices are accepted, unmatched entries appear in `Report.UnmatchedDeviceSelectors`, and empty bounds fall back with `device-selection-empty` or error in strict mode.
- Added per-assignment accel dispatch with `single`, `auto` (default), and `forced` shard strategies. `auto` uses the recorded 32k/8k saturation floors, assignments report placement, wall time, chunks, and fallback, and a failed assignment falls back only its own rows. Correctness is verified bit-identically on single-device hardware; multi-GPU wall-clock measurement is unmeasured.
- Acceleration now logs one session-scoped info line at first device use and first qualifying fallback, with per-execution placement at debug level. The root `Config` log level controls the output. `Config.SetAcceleration` also logs one info line per actual state transition, so a mid-run toggle is visible at the moment it happens.

### `stats`

- `PCA` returns an error instead of panicking on a table with no columns. The shape guard existed but sat 34 lines below the `mat.NewDense` call it was meant to protect, so a zero-column table crashed the caller with `mat: zero length in matrix dimension`.

- Added `Predict` to linear, polynomial, exponential, and logarithmic regression results. It follows the GLM prediction signature and returns response-scale point predictions for new data, with predictor-count and row-length validation. R's standard errors and prediction intervals remain outside the current API.
- Added `KMeansResult.Assign` to apply fitted centers to new observations and return the one-based center index with its squared Euclidean distance.
- `PCAResult` now returns the fitted per-column centering and scaling parameters, together with the training scores, so callers can project new observations with the same decomposition.
- Logistic and Poisson regression results now expose the fitted `Link`, matching `GLMResult.Link`, so callers can reproduce response predictions from linear predictors outside `stats`.
- Passing a nil table to a clustering or decomposition entry point now returns an error instead of panicking. `KMeans`, `DBSCAN`, `Silhouette`, `HierarchicalAgglomerative`, `PCA` and `KMeansResult.Assign` all dereferenced the table before validating it, so both a nil interface and a typed nil crashed the caller.
- **BREAKING**: a value that cannot be read as a finite number is now refused instead of being treated as zero. This affects `LinearRegression`, `PolynomialRegression`, `ExponentialRegression`, `LogarithmicRegression`, `PoissonRegression`, `GLM`, `Correlation`, `Covariance`, `CorrelationMatrix` and `CorrelationAnalysis`, in the target as well as the predictors. These routed every value through a conversion with no failure channel, so a missing value, a blank or text silently became `0` — one blank among six observations moved a Pearson coefficient from 0.9992 to 0.9879 with no error and nothing downstream able to tell. Clustering, PCA and KNN already refused; factor analysis already deleted the observation. The error names the series and the row, and `Docs/stats.md` now states each family's treatment.
- Added `RidgeRegression` and `LassoRegression`, using scikit-learn's objectives exactly — L2 penalty `||y − Xβ||² + α·||β||²` solved in closed form, L1 penalty `(1/2n)·||y − Xβ||² + α·||β||₁` by coordinate descent — with the intercept unpenalized and no standardisation, both verified coefficient-for-coefficient against scikit-learn. Ridge handles collinear predictors that make `LinearRegression` fail; lasso drives priced-out coefficients to exactly zero and reports non-convergence instead of hiding it. Neither result carries standard errors, t or p values, because classical inference does not apply to penalized estimates. scikit-learn rather than R's glmnet is the reference: glmnet standardises by default and scales its penalty differently, so it computes different coefficients from the same data.
- Added `WeightedLinearRegression` (WLS): weighted normal equations with exact classical inference — coefficients, standard errors, t and p values, weighted R² and predictions all verified field-for-field against statsmodels' `WLS`. Weights must be strictly positive; a zero weight is refused rather than guessed into exclusion semantics, because references disagree on the degrees of freedom and standard errors matching nobody would be the result.
- Auto-algorithm KNN can use the GPU: blank-import `accel/knnbridge` and profitable shapes route through the exact-nearest device operation, whose answers the CPU recomputes in `float64` — device results are identical to brute force, index for index, verified on hardware, and the win is measured in the wiring's own direction (1.4x at 2k test rows to 3.7x at 10k, on 100k×32 against all cores). Explicitly named algorithms, `k > 7`, small shapes and machines without a device all run the CPU path unchanged, and without the import `stats` carries no accelerator dependency.
- CPU auto-algorithm KNN now probes a deterministic sample of the caller's test rows before accepting a ball tree. When pruning examines too much of the training set, it falls back to exact brute force; explicitly named algorithms remain honored, and results are bit-identical because the probe only selects the exact search path.

### `nn`

- Added `Sequential.Fit` as a deterministic training front door with explicit optimizer and loss selectors, seeded `rng.Perm` minibatches, optional `Predict`-based validation, callback progress, and one root-logger info line per epoch. The Fit path reproduces the documented tape loop's loss sequence digit-for-digit; schedules, early stopping, checkpointing, and `DataTable` integration remain outside v1.
- Added the resize operator wave, scoped by inventory of two more published checkpoints: `Resize` (nearest and linear, scales or sizes, asymmetric and pytorch_half_pixel coordinate modes), opset-9 `Upsample`, `Floor`, `InstanceNormalization`, and reflect-mode `Pad`. FCN-ResNet50 (semantic segmentation) and mosaic-9 (fast neural style) now run unmodified and match `onnxruntime`; ConvTranspose and TopK stay unbuilt because no target model needs them.
- Large 2-D float32 MatMuls are now device-on by default without a blank import. Only products at or above the measured 16Mi MAC floor consult the device; batched or smaller products remain on the byte-identical CPU path. `INSYRA_ACCEL_DISABLE_WGPU=1` and `nn.RegisterDeviceMatMul(nil)` restore CPU-only execution. Measured on the 8-core M3 / Metal, the device result is bit-identical to the CPU's at every ladder rung, wins from 1.35x at the floor to 52x at 4096-square, and drops the measured encoder layer from about 0.9s all-core CPU to 234ms.
- Extended the autodiff tape with CNN VJPs for 2-D Conv, MaxPool, AveragePool, GlobalAveragePool, and inference-mode BatchNormalization. Grouped Conv, asymmetric padding, strides, pooling denominator semantics, and all three BatchNormalization gradients are covered by finite differences; a deterministic CNN now matches PyTorch through one Adam step.
- Added a `Layer` and `Sequential` surface over the autodiff tape, with eager dimension checks, seeded He-initialized `Dense`, activation, `Dropout`, `Flatten`, and `Func` layers. `Predict` structurally skips training-only layers, names parameters like torch `nn.Sequential`, and loads torch Linear SafeTensors with the `[out,in]` to `[in,out]` boundary transpose. The Sequential MNIST proof reproduces mean losses `0.350281` and `0.163855` and reaches `95.84%` accuracy after two epochs.
- Completed the trainable layer catalog with `Conv2D`, `MaxPool2D`, `AvgPool2D`, `GlobalAvgPool`, training/eval `BatchNorm2D`, `LayerNorm`, and `Embedding`. Training BatchNorm matches torch's biased normalization, unbiased running variance update, and three-term gradient; Embedding scatter-adds repeated indices. Torch state-dict loading accepts convolution and normalization buffers, and the gated CNN catalog proof reaches `97.27%` on MNIST in two epochs using a documented 30,000-row subset.
- Added deterministic `SaveSafeTensors`, `Sequential.SaveWeights`, and `Sequential.ExportONNX`. Saved state dicts use torch names, include BatchNorm running statistics, and reverse the Dense transpose; ONNX exports supported inference layers, omits Dropout, and refuses Func or Embedding by layer position. Trained MLP and CNN exports round-trip through `nn` exactly and through `onnxruntime` within float32 tolerance.
- Added fused mean `MSELoss` and `BCEWithLogitsLoss` tape operations, per-parameter `SGDMomentum`, `CosineAnnealingLR`, and global-norm `ClipGradNorm`. A six-step BCE training recipe matches PyTorch at every step for learning rate, loss, pre-clip norm, and all parameters.
- Added torch-compatible `MultiHeadAttention(embed, heads)` and `Residual(layers...)` layers. Mask-free batch-first self-attention composes existing tape operations, nested layer state names round-trip through SafeTensors with torch projection transposes, and a layer-built encoder matches PyTorch through one AdamW step. ONNX export refuses both composite layers by position and kind.
- Added detector-oriented ONNX inference support: `LeakyRelu`, `Exp`, `Ceil`, `Round`, `Tile`, `ReduceMin`, batched `NonMaxSuppression`, and `Loop` with validated GraphProto bodies, child scopes, loop-carried values, and scan outputs. One-op and synthetic Loop parity pass against `onnxruntime`, and gated tiny-YOLOv3 parity matches exact selection indices and f32 boxes and scores.

### `ml`

- ONNX export now produces models an independent runtime accepts. Two defects had survived because the round-trip verification requires `python3` with `onnxruntime` and had silently skipped on every machine it ran on. Every non-string attribute carried a stray empty string data field, which onnxruntime rejects as an invalid graph before running anything; and tree nodes were written deepest-leaf-first, while the runtime treats each tree's first array entry as its root — so it walked one node and refused the model. Nodes are now written root-first, and the round-trip — linear, logistic, both trees, and a pipeline — passes against onnxruntime.

- `mltest.RunConformance` now uses the training labels it is given. It took them and discarded them, so a caller passed a value nothing was checked against. For a `Classifier` it now verifies that `Classes()` accounts for every label the model was fitted on — a class set omitting one describes a label the model can never predict.

- Added `ml.Clusterer`, an optional interface a clustering model implements to say its predictions are group assignments rather than measurements, reporting how many groups the fit converged on. A regression metric is now refused against one. Previously `KMeansModel` was neither a `Classifier` nor a continuous predictor, so nothing stopped `RMSE` from scoring its cluster ids and returning an arithmetically correct number about nothing.

- A metric written outside the package can now say what input it needs. `ClassLabelMetric` and `ProbabilityMetric` are exported, so a caller-written metric can request class labels or probabilities the way the built-in ones do. Previously the routing keyed off unexported marker interfaces, so an external metric could never request probabilities — it silently received the model's predictions instead, with `Prediction.Probabilities` nil and no error. Both interfaces are now read rather than merely detected: implementing one and answering `false` is the same as not implementing it. `Prediction`'s fields document which are populated when.

- `mltest.RunConformance` now checks the probability ordering by value, not only by column name. It compared column names against class names, which a model that derives its names from its own `Classes()` list satisfies by construction — so a model whose probability values sat under the wrong labels passed a check written to catch exactly that. For every row, the class `Predict` returns must now be the class whose column holds the largest probability. Its renamed-column check was also strengthened: the renamed name was a superstring of the original, so an error naming only the incoming column satisfied it.

- `ROCAUC` now refuses a true label that belongs to neither probability class, instead of treating it as negative. It previously reported confident discrimination — an AUC of 1 with a nil error — over data it had not understood, while `LogLoss` refused the identical input. The two metrics no longer disagree.

- Added a common estimator and transformer protocol over the fitted models already provided by `stats`, with name-based feature binding, optional probability capabilities, PCA transformation, KNN wrappers, and `ml/mltest` conformance checks.
- Added `ml.NewPipeline` and `ml.NewColumnTransformer` for fitting preprocessing and a model together, scoping transformers to named columns, and reusing the fitted result without preprocessing leakage.
- Added seeded k-fold and stratified splitting, estimator cross-validation with one score per fold, and classification and regression metrics including accuracy, log loss, ROC AUC, confusion matrices, RMSE, MAE, and R².
- Added deterministic histogram decision-tree classification and regression with quantile-binned numeric features, categorical subset splits, learned missing-value routing, bounded growth, class probabilities, and feature importances.
- Hardened the `ml` protocol and pipelines: unnamed feature schemas and unsupported regression offsets are rejected, logistic models distinguish labels from probabilities, fitted pipelines preserve supported capabilities and input order, and decision-tree regression retains precision for small targets.
- Added dependency-free ONNX export for linear and logistic models, decision trees, and fitted pipelines with supported scalers and encoders. Unsupported models are refused before writing, and the export tests use an independent `onnxruntime` round trip when it is available.
- `Score` evaluates a fitted model on held-out data with a supplied metric, without refitting. It runs the same compatibility check and prediction assembly as `CrossValidate`, so a metric needing probabilities — or needing class labels from a model that reports probabilities — is served identically either way. scikit-learn attaches a default metric to the estimator class; Go has nowhere to hang that, so the metric is an argument.
- **BREAKING** for metrics defined outside the package: `Metric` gains `Direction`, declaring whether a larger or smaller score is better. `CrossValidationResult` carries it, and `Better` compares two results by it. Without this a caller comparing two means picked the worse model half the time, since half the built-in metrics improve as their score rises and half as it falls. A metric that returns a rankable score while declaring `NoDirection` is refused rather than defaulted.
- Fitted pipelines report `TransformedFeatureNames`, the columns the final estimator was fitted on after every step ran. A pipeline over two columns that encodes one into three reported two feature names and four importances, with nothing to align them. The conformance helper now requires a model's importance count to match its feature-name count.
- Added `PrecisionMetric`, `RecallMetric` and `F1Metric` with macro, micro, weighted and binary averaging, plus the `Precision`, `Recall` and `F1` direct helpers, all verified against scikit-learn's `precision_recall_fscore_support`. The default averaging is macro rather than scikit-learn's binary-with-`pos_label=1`, which over arbitrary labels is a guess; binary averaging requires the positive class to be named, because unlike ROC AUC these scores change with which class is positive. A never-predicted class contributes precision 0, matching `zero_division=0`.
- Added `FitRidgeRegression` and `FitLassoRegression`, wrapping the new `stats` estimators into the estimator protocol with name-based feature binding, conformance-checked.
- `GridSearch` cross-validates named candidate estimators on identical folds — drawing and reporting one seed when none is supplied, so the comparison is fair and reproducible — ranks them by the metric's declared direction with ties keeping the earliest candidate, and returns the winner refitted on the full data. The grid arrives already expanded as named estimators, because parameter-grid expansion is the `clone()` reflection this protocol deliberately does not have.
- Added random forests (`FitRandomForestClassifier`, `FitRandomForestRegressor`): bootstrap resampling expressed as row multisets over one shared preparation, per-split feature subsampling (√p for classification, all p for regression), probability-averaged prediction, and importances as the renormalized mean of the per-tree importances. Trees fit in parallel but every draw derives from one seed, reported on the model when drawn, so the same seed always reproduces the same forest. Classes are collected from the full target before resampling, so a bootstrap sample missing a class cannot misalign probability columns.
- Added gradient boosting (`FitGradientBoostingRegressor`, `FitGradientBoostingClassifier`): squared-loss residual fitting for regression, binary logistic loss with Newton-step leaf values for classification, scikit-learn's defaults, early stop on zero residuals with the ran-stage count reported. Multiclass targets are refused with the limit named rather than approximated.
- Added `FitWeightedLinearRegression(x, y, weights)`. The weights apply to that fit only: `CrossValidate` has no weights channel, so the limitation is documented rather than silently misaligned.
- `CrossValidateWeighted` routes sample weights to fitting: each fold's estimator receives its training rows' weights, subset with the same indices that built the fold, so alignment holds by construction. `Estimator` gains an optional `FitWeighted` — everything that does not mention weights is unchanged. Held-out scoring stays unweighted, matching scikit-learn's default; an estimator without `FitWeighted` is refused rather than silently fitted unweighted.
- ONNX export covers the new families: ridge, lasso and WLS through the linear-regressor path, and both forests and both boosters as multi-tree ensembles — a forest's leaves scaled by 1/T so the runtime's sum is the average, boosting with the learning rate baked into leaf weights and the prior as base value. Binary classifiers use the runtime's single-score convention: written with both classes' weights, the probabilities came back exactly right while every label came back 1, so two-class ensembles carry one score per leaf and the runtime computes the complement and the half-threshold label. All seven families pass the independent onnxruntime round trip.
- Decision trees gained `ExactSplits`: every midpoint between adjacent distinct numeric values is a split candidate — scikit-learn's CART search — alongside the default histogram search. The split criteria already matched (Gini, variance), so the exact tree is verified prediction-for-prediction against scikit-learn: classification labels exact on a probe grid, regression within single-precision tolerance. Histogram stays the default for its O(MaxBins) cost; combining the two options is refused, and ensembles inherit the choice.
- Exported logistic models now carry two coefficient rows (skl2onnx's binary convention), fixing the probabilities output under onnxruntime: the single-row form relied on the runtime applying the LOGISTIC transform on its binary path, and onnxruntime does not — it returned the raw decision score as the probability, unnoticed while the round trip compared labels only. Found by `nn`'s double-reference round trip; labels were always correct.
